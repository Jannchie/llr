# ZcTaskChromaSuppres:lo/hi 怎么随 ISO 插值(补 PIPELINE §7.5)

> **2026-09-10 实测:** 四帧十二块 tile 100.0000% 逐位;`lv[0xc]` 恒 0(不是 ISO 轴);lv 与 calib 不是同一块内存;B→hiY 的 LUT 链是往返恒等。见 measured-chroma-gap §2.24.1。已接入 worker/web。

* 反编译产物:`tools/chroma_suppres_decomp.c`
* exec RVA **`0x36e920`**(1289 字节)。函数不长,已逐句读完
  (含 4 张跳转表,Ghidra 没恢复,用 `jt.py` / 反汇编手工补齐)。

## 0. 先修正 PIPELINE §7.5 的两处

1. **不是 `f/255`,是 `* f >> 8`。** `f = 255` 时色度实际乘 `255/256 = 0.99609`,
   中间调**并非完全不动**,每次过一遍会掉 0.39%。
2. 「lo/hi 随 ISO 插值」—— 真正的插值轴是 **RAW tag `0x74a5` / 300**,单位是
   **档(stop)**,锚点在 **0 / −1 / −2** 三处;而且插值出来的两个量并不是
   「lo 和 hi」,是 **一条阈值** 和 **一个斜率**(见 §2)。

## 1. 主体

```c
/* plane0 = Y (int16, 有符号!), plane1 = Cr, plane2 = Cb (uint16, 中点 0x8000) */
arw   = dynamic_cast<ZcARW*>(a[0]);
calib = arw->vt[0xd8](arw, a[1][0x1e0]);          /* 逐图标定块,= PIPELINE 的 lv */
lv    = *(*(task + 0x68) + 0xc8);                 /* 同一块内存,另一条取法 */

model = calib[0x2c];                              /* 机型码 0x100 .. 0x115 */
x     = calib[0xc] / 300.0;                       /* ← RAW tag 0x74a5,单位 1/300 档 */

/* ---- 六个锚点(见 §2 的机型表) ---- */
A0 = ...; A1 = ...; A2 = ...;        /* "斜率族" */
B0 = calib[0xf06]; B1 = ...; B2 = ...;  /* "阈值族" */

A = A0;  B = B0;                                  /* x >= 0 用 0 档的值 */
if (-2.0 <= x && x < -1.0) { A = (A1-A2)*(x+2) + A2;  B = (B1-B2)*(x+2) + B2; }
if (-1.0 <= x && x <  0.0) { B = (B0-B1)*(x+1) + B1;  A = (A0-A1)*(x+1) + A1; }
/* 注意:两支的 A/B 赋值顺序在原文里是交叉的,但结果等价;x < -2 时两者保持 0 档值 */

/* 三角斜坡,x = -1 处取 1.0 */
ramp = 0.0;
if (-2.0 <= x && x <= -1.0) ramp = x + 2.0;
if (-1.0 <= x && x <=  0.0) ramp = -x;

/* ---- 把线性域阈值 B 送过整条 tone 链,换算到 Y 域 ---- */
sc  = (int16)lv[0x18ee] * (1.0/64.0);
t   = min(B, 0x3fff);
t   = (int)( (int16)lv[0x79962 + 2*(int16)lv[0x89962 + 2*t]] * sc );
t   = min(t, 0x7fff);
hiY = (int16)lv[0x318fc + 2*(int16)lv[0x118f6 + 2*t]];   /* 0x118f6 = tone LUT, 0x318fc = YGamma LUT */

loY = (B == 0) ? 0 : (hiY * (int16)calib[0xf0e]) / B;

slope_lo = (int)( (int16)calib[0xf0c] / sc );
slope_hi = (int)( A / sc ) + (int)(ramp * 150.0);        /* _DAT_140467688 = 150 */
hiY     += (int)(ramp * -1200.0);                        /* _DAT_1404676a0 = -1200 */

/* ---- 逐像素 ---- */
for each pixel:
    Y = (int16)plane0[i];
    if      (Y < loY)  f = 255 - (((loY - Y) * slope_lo) >> 12);
    else if (Y > hiY)  f = 255 - (((Y - hiY) * slope_hi) >> 12);
    else               f = 255;
    f = clamp(f, 0, 255);

    plane0[i] = max(Y, 0);                               /* Y 顺手钳到非负 */
    plane1[i] = trunc_toward_zero((plane1[i] - 32768) * f / 256) + 32768;   /* Cr */
    plane2[i] = trunc_toward_zero((plane2[i] - 32768) * f / 256) + 32768;   /* Cb */
```

取整细节:`(short)(v + (v >> 31 & 0xff) >> 8)`,即负数加 255 再算术右移 8 ——
**向零取整**,不是向下取整,也不是四舍五入。

## 3. 关于新语料的 ISO 跨度 100~8000

`x = tag0x74a5 / 300`,锚点 0 / −1 / −2 档。若 `0x74a5` 直接编码
「相对基准 ISO 的负增益」,ISO 100→0、ISO 200→−300、ISO 400→−600,
则 ISO ≥ 400 就落到 x ≤ −2 —— 而 **x < −2 的分支代码里 A、B 都保持 0 档值不变**
(两个 `if` 都不成立)。这看起来像 bug,也可能说明 `0x74a5` 的量纲不是我猜的那样。
**这一条不要照我的猜测写代码,请动态读一次 `calib[0xc]`,配 ISO 100/400/3200/8000
四张图就能定标。** 这是本节唯一必须实测的量。
