## 1. 算法

```
# ---- 参考值:按亮度在中心像素和 9×9 均值之间插值 ----
mean = boxsum(9×9 以 (x,y) 为中心) / 81
t_w  = tableA[mean]                                   # int32, 满刻度 0x400
ref  = (centre * t_w + (1024 - t_w) * mean) >> 10

# ---- sigma 滤波:只接受与参考值足够接近的邻居 ----
thr = tableB[centre]                                  # 以中心电平为索引
sum, count = centre, 1
for n in 3x3 的 8 个邻居:
    if abs(n - ref) < thr:
        sum += n; count += 1
avg = sum / count                                     # idiv, 向零取整

# ---- 细节回注:与 RawNR 同一套公式和同一对字段 ----
d   = ((int16)highpass[y][x] * GAIN) >> 8              # GAIN  = calib[+0xc00ec]
out = clamp(avg + clamp(d, -LIMIT, +LIMIT), 0, 0x3fff) # LIMIT = calib[+0xc00f8]

# ---- 强度淡出 ----
if strength != 0.0:
    out = orig[y][x] * strength + out * (1.0 - strength)
```

输出钳到 **0x3fff**,即这一级的 Y 是 14 位。

### 两张表 —— 已经抓到了,不用新的动态手法

`rawnr_probe.py` 抓的六张表在 `calib + 0x000d0 + k*0x20000`(k = 0..5),所以:

| 参数 | 地址 | = 哪张 | 索引 | 用途 |
|---|---|---|---|---|
| arg3 | `calib + 0x200d0` | **tbl1** | **中心像素电平** | 阈值 `thr` |
| arg5 | `calib + 0x800d0` | **tbl4** | **9×9 均值** | 插值权重 `t_w` |

两者各 `0x8000` 项 int32(caller 传的 `0x8000` 就是项数)。

> ⚠️ 别按「0x200d0 是第一张」去数,那会得出 tbl0 / tbl3。表基址是 `+0xd0`,
> 不是 `+0x200d0`。

六张表其实是**两组各三份**(R / G / B),BSNR_Y 作为 Y 级取的是中间那份:

* `tbl0 / tbl1 / tbl2` 三张完全相同 —— 阈值,分段线性
* `tbl3 / tbl4 / tbl5` 三张完全相同 —— 权重

在 `tools/rawnr_tables_DSC03036.npz` / `_fl_test.npz` / `rawnr_tables.npz`
三个素材上都核过:

| 素材 | tbl1(阈值) | tbl4(权重) |
|---|---|---|
| DSC03036 | 13 → 61,拐点 idx 52 / 2521,之后持平 | 常量 **512** |
| fl_test | 11 → 53,拐点 idx 60 / 2530 | 常量 **512** |
| DSC04568 | 3 → 16,拐点 idx 151 / 1973 | 常量 **512** |

一阶差分只取 `{0, 1}`,正是 static-rawnr.md 里那条
`tbl[i] = clamp(((clamp(i,lo,hi) - lo) * slope >> 12) + base, 0, 0x3fff)`。
「先线性、过约 1/6.5 全刻度后持平」的形态与 `_CurveVST` docstring 描述的
Sony 噪声曲线一致。

**权重 512 是 `trunc((t+100)/200 * 1024)` 在 t = 0 的值**(static-rawnr.md §7.3),
而核心里除的正是 `>> 10` = 1024。于是中性档位(UI 50)下

```
t_w = 512  →  ref = (centre + mean) / 2
```

参考值就是中心像素与 9×9 均值的**等权平均**。两端:

| t | UI | t_w | ref |
|---|---|---|---|
| −100 | 0 | 0 | 9×9 均值 |
| 0 | 50 | 512 | (centre + mean) / 2 |
| +100 | 100 | 1024 | centre |

即 **Amount 滑块控制的是「邻居跟谁比」** —— 从局部均值一路滑到中心像素本身。
这条是两次独立解码(RawNR 的建表 与 BSNR_Y 的核心)互相验证出来的。

注意阈值的绝对量级很小:DSC03036 上 13..61,而满刻度是 `0x3fff` = 16383,
也就是 **0.08% .. 0.37%**。这是个保守的 sigma 滤波,只接受与参考值相差约
1~2 个噪声 sigma 之内的邻居。

### 认除法

`0x1948b0fd` + `sar edx, 3` = **除以 81**。验过 n = 80 / 81 / 162 / 6561 四点。

### tap 集合是完整 3×3,别被反汇编骗了

编译器把 8 个邻居拆成了四段:4 个对角是展开的直线代码,上/下各一条,
左/右被写成**退化的循环**(`r10 = x-1; while (r10 < x)` 和
`r10 = x+1; do {} while (r10 <= x+1)`,各只跑一次)。
只读前半段会误以为「只用对角邻居」。

## 2. 强度从哪来(`0x14039d050` 开头)

```
if ([r8]->+0x144 == 3 && params[+0x21c] < -50)
    strength = 2 * (-50 - params[+0x21c]) / 100.0f      # 除数是 0x1404df210 = 100.0f
else
    strength = 0
```

`+0x21c` 与 YNR 的 `P` **是同一个字段**(recipe 设置键 `0x8027`,见 static-ynr.md §2)。

**关键:混合权重 `strength` 压在「原图」那一侧**(`0x1404debbc = 1.0f`):

| `t = params[+0x21c]` | UI | strength | 输出 |
|---|---|---|---|
| `t >= -50` | ≥ 25 | 0 | **完全滤波** |
| `-100 < t < -50` | 0..25 | 0 → 1 | 线性淡出 |
| `t = -100` | 0 | 1.0 | 原图,**完全关闭** |

所以 BSNR_Y 是**常开基线**,只在滑块降到 UI 25 以下才淡出。
这与 static-rawnr.md §7.3 的「UI 0 ⇒ strength 0 ⇒ 阈值表全零」一致 —— 两级都在
UI 0 关掉。

> ⚠️ 我第一遍把混合方向读反了,以为 BSNR_Y 只在 UI < 25 才启动。
> 权重在原图那一侧,结论正好相反。

`[r8]->+0x144 == 3` 是个门:不等于 3 时 `strength` 保持 0,也就是**恒为完全滤波**,
淡出根本不生效。这个 `0x144` 是什么还没查。

## 3. 与 YNR 合起来看

同一个 `t` 驱动两级,分工清楚:

| t | UI | BSNR_Y | YNR |
|---|---|---|---|
| −100 | 0 | 关 | `P<0`,朝远离中值外插(锐化) |
| −50 | 25 | 刚好全开 | 同上,较弱 |
| 0 | 50 | 全开 | `P=0`,**恒等** |
| +100 | 100 | 全开 | 混向中值 100% |

即:**BSNR_Y 是基线降噪,YNR 是往上加的那一档中值降噪**,
中性档位(UI 50)下只有 BSNR_Y 在工作。

## 4. 实测:这一级几乎不降噪(`tools/bsnr_ref.py`)

用 DSC03036 的真实表(tbl1 / tbl4)和真实回注参数
(`detail_restore` 给的 **GAIN = 249 / LIMIT = 1023**),在 σ = 30 的平坦噪声场上:

| GAIN | 噪声 std | × | 孤立脉冲残留 |
|---|---|---|---|
| 249(机身实际) | 25.6 | **0.85** | **28.4%** |
| 128 | 15.1 | 0.50 | 28.4% |
| 0(完全不回注) | 7.7 | 0.26 | 25.0% |

**两条都出乎意料,而且都是负面结果:**

1. **降噪量只有 ×0.85。** GAIN = 249/256 把细节连同噪声几乎原样加了回去。
   这与 static-rawnr.md 对 RawNR 的结论同形(「只吃掉约一成细节」)——
   代价是也只去掉约一成噪声。
2. **sigma 滤波对孤立脉冲毫无作用。** 残留在 GAIN = 0 时仍有 25%,所以不是
   回注造成的。算一下就清楚:低通在脉冲中心给出
   `(4*16383 + 2*4*1200 + 4*1200) / 16 = 4995`,相对背景 1200 正好是 25%。
   而 sigma 滤波一点没减 —— 脉冲的邻居全在阈值(61)之外,`count` 保持 1,
   输出就等于中心值。**边缘保持逻辑主动保护了脉冲**,和 garrote 收缩是同一个
   结构性缺陷。而且脉冲被低通摊到 3x3,周边 8 点从 1200 涨到 1636 / 2585。

顺带把噪声模型对上了:`NoiseModel(lo=0, hi=2560, base=13, slope=78)`。
`slope = 78` 意味着 `i*78 >> 12` 每约 52.5 个索引才 +1,所以表在 idx **52**
才开始变化、到 **2521** 饱和于 61 —— 与抓取的 tbl1 逐点吻合。

> ⚠️ 所以「Edit 用中值所以能杀脉冲」这个说法要限定清楚:**中值是 YNR,
> 而 YNR 在中性档位是关的**。常开的 BSNR_Y 不杀脉冲。
> Edit 在默认设置下对脉冲同样无能为力。

## 5. 对 llr 的意义

BSNR_Y 才是要复刻的那一级 —— 它默认就在跑,而 YNR 默认是恒等的
(`static-ynr.md` §2:`+0x22c` 构造默认 0)。

它的三个组成部分,llr 现在**一个都没有**:

1. **亮度自适应参考值**(9×9 均值 ↔ 中心像素按 `tableA[mean]` 插值)。
   llr 的小波收缩没有任何与局部亮度相关的参考量。
2. **sigma 滤波**(按 `|n − ref| < thr` 挑邻居再平均)。这是个
   **选择性平均**,对孤立脉冲天然免疫 —— 脉冲进不了自己的邻居集合,
   而 garrote 收缩会把它完整保留(见 `denoise.py` 自己的 docstring)。
3. **细节回注**用的是和 RawNR 完全相同的 `clamp(d*GAIN/256, ±LIMIT)`,
   同一对字段 `+0xc00ec` / `+0xc00f8`。llr 里 `DetailRestore` 已经实现了这个
   形状(`sony/rawnr.py`),可以直接复用。

### 复现障碍(和 YNR 同一个)

`thr` / `t_w` 两张表都以 **Sony 的 Y 域 14 位电平**为索引,不是场景线性。
落点仍应在 tone 曲线之后(`runSonyPost` 那一级),而不是 worker 的马赛克域。

两张表**已经在库里了**(见 §1「两张表」),DSC03036 的那份就是
`tools/rawnr_tables_DSC03036.npz` 的 `tbl1` / `tbl4`。所以写一份参考实现
不再需要任何逆向工作 —— 缺的只是 Y 域的定标。

### 还缺的一块:高通平面

`d = (int16)highpass[y][x]` 里那个平面由 `0x14039c960` 建(exec 前调用一次),
还没读。RawNR 那边同位置是「原图减低通的 3×3 高通」,大概率同构,但没验。
在它解出来之前,细节回注只能按 RawNR 的形状代入。
