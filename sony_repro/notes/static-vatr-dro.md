# ZcTaskVatr(DRO)静态反编译

* 反编译产物:`tools/vatr_decomp.c`
* exec RVA **`0x366920`**(4845 字节)。函数体是 SSE 主循环 + **标量收尾循环**,
  两者同构 —— 下面的伪代码取自标量收尾段(`top0.c` 里 2958–3039 行对应处),
  已与 SSE 段逐项核对(见 §6)。

## 0. 一句话结论

**DRO = 双边网格(bilateral grid)局部色调映射。**
`gain = 2^( Tone(局部均值) − 局部均值 )`,三通道同乘 → 天然保色。
`Tone` 是一条 **10 节点分段三次 Bézier**,
**Auto 档位的那条曲线是相机写在 ARW 里的(SR2 tag `0x781b` / `0x781c`),
不是引擎按画面现算的。** 引擎按画面算的只有「局部均值」那一半。

## 2. 逐像素伪代码

```c
/* plane0 = R, plane1 = G, plane2 = B,uint16,14 位左移 1 位存(读时 >>1,写时 *2) */
R = plane0[x] >> 1;  G = plane1[x] >> 1;  B = plane2[x] >> 1;

y     = R*0.1495f + G*0.2935f + B*0.0570f;        /* = (0.299R+0.587G+0.114B)/2 */
Ylog  = to_log(vatr, 2*y);                         /* FUN_140189930 */

blk   = pick_4_blocks(vatr, (int)(x*S), (int)(y_row*S));   /* FUN_14018b680 */
(den, num) = trilerp(vatr, blk, Ylog);                     /* FUN_140368260 */
Mlog  = (den == 0.0f) ? vatr[0x70] : num / den;    /* 边缘感知的局部对数亮度均值 */

/* 曲线查表:104 项,步长 vatr[0x70]/104 */
i     = (int)(Mlog * 8.0f);
frac  = (Mlog - i * 0.125f) * 8.0f;
Tone  = (i < 0x67) ? lerp(curve[i], curve[i+1], frac) : vatr[0x960];

C     = (st[0x238] == 1) ? 1.0f : vatr[0x74];      /* st = a[1],DRO 模式 */
g     = pow(2.0f, C * (Ylog - Mlog) + Tone - Ylog);

k     = 1.0f + (g - 1.0f) * ((g > 1.0f) ? vatr[0x964] : vatr[0x968]);   /* 两者都 = 1.0 */

plane0[x] = clamp(R*k, 0, 16383) * 2;
plane1[x] = clamp(G*k, 0, 16383) * 2;
plane2[x] = clamp(B*k, 0, 16383) * 2;
```

`C = 1.0` 时式子塌缩成 **`g = 2^(Tone(Mlog) − Mlog)`** —— 增益只是局部均值的函数。

> 这与动态那边「按输入值分箱解释掉 76% 增益方差」不矛盾:
> **双边网格的第三个轴就是像素自己的 `Ylog`**,同一格子里只有亮度相近的像素
> 被平均进 `Mlog`,所以 `Mlog ≈ Ylog + 小偏移`,看起来像逐像素。
> 而「残差与邻域均值的相关随核尺度单调上升、2052px 处还在升」正是
> 粗网格只有 8×6 的直接后果(整幅 7008 宽 / 8 ≈ 876 像素一格)。

## 3. log / exp 变换

```c
float to_log(vatr, v) {                         /* FUN_140189930 */
    v *= vatr[0x54];                            /* = 1.0 */
    if (v < 0)      return 0.0f;
    if (v >= 16384) return log2f(v);            /* DAT_1404df29c = 16384 */
    t = v / 8.0f;  i = (int)t;
    return lerp(LOG[i], LOG[i+1], t - i);       /* LOG[i] = log2(i*8) */
}
float to_lin(vatr, v) {                         /* FUN_140186e00,SSE 路径用 */
    if (0 <= v && v < 14.0f) {                  /* DAT_1404df1bc = 14 */
        t = v / 0.0068359375f;  i = (int)t;
        return lerp(EXP[i], EXP[i+1], t - i);
    }
    return powf(2.0f, v);
}
```
标量收尾段直接调 `pow(2, ·)`,SSE 主循环走 `to_lin` LUT —— **两条路径有
微小差别**(LUT 步长 14/2048 ≈ 0.00684 对数级),复刻时随便挑一条。

## 4. 双边网格

* **建网格的输入是预览图,不是全幅。** `FUN_1401887b0` 第一件事是
  `preview = arw->vt[0x110]()`,取它的 `+8/+0xc` 当宽高算出网格几何。
  按 `arw->vt[0xf0]()` 的返回值 1/3/4 分别调
  `FUN_140188b60` / `FUN_140189220` / `FUN_1401895a0` 累加(三种预览像素格式)。
* 网格 = **8 × 6 空间格 × 14 亮度箱**,每格 0x40 字节,里面两条数组:
  `blk+0x20`(值和 num)与 `blk+0x28`(权重和 den)。
* `FUN_14018b680` 给出 4 个相邻格 + 双线性权重;
  `FUN_140368260` 在 (x, y, Ylog) 三个方向做三线性插值,分别插 num 和 den。
* `FUN_140189bd0` / `FUN_14018a460` 做块间 3×3 平滑
  (`FUN_140189dc0` / `FUN_140189ff0` / `FUN_14018a200` 分别是角/边/内点)。

⚠️ **渲染时的坐标换算没解出。** 调用是
`FUN_14018b680(vatr, (int)(x * S), (int)(y * S), &blk)`,
其中 `S = (a[0x18] == 2) ? 8.0f : 1.0f`(`DAT_1404df190 = 8`)。
`x`/`y` 是 tile 在整幅里的坐标,而网格几何是按**预览图**尺寸算的。
`S=8` 那一支说明预览大约是全幅的 1/8,但两者到底怎么对齐要动态量。

## 5. 色调曲线 —— Auto 的答案在这里

`FUN_14018ad50(vatr, level, ..., flag, knots_u16, ctrl_u16)`,RVA `0x18ad50`:

```c
if (level == -1 && flag != 0) {
    /* ★ AUTO:直接用 RAW 里的曲线 */
    for (i=0;i<10;i++) knot[i] = knots_u16[i] / 1024.0f;    /* DAT_1404dea7c = 1/1024 */
    for (i=0;i<28;i++) ctrl[i] = ctrl_u16[i]  / 1024.0f;
} else {
    /* 手动档:在 10 条内置预设之间插值 */
    L  = (level == -1) ? 50 : level;
    i0 = L / 10;  i1 = min(i0 + 1, 9);
    u  = (i0 == i1) ? 0.5f : (L - i0*10) / 10.0f;
    knot[k] = lerp(vatr[0x13c + i0*0x98][k], vatr[0x13c + i1*0x98][k], u);   /* 10 项 */
    ctrl[k] = lerp(vatr[0x164 + i0*0x98][k], vatr[0x164 + i1*0x98][k], u);   /* 28 项 */
}

step = vatr[0x70] / 104.0f;                     /* _DAT_1404df218 = 104 */
for (i = 0; i <= 0x67; ++i) {
    xx = i * step;
    j  = 第一个使 xx < knot[j+1] 的 j,否则 9;      /* 9 段 */
    d  = knot[j+1] - knot[j];
    u  = (d == 0) ? 0 : (xx - knot[j]) / d;
    b  = 3*j;
    v  = (1-u)^3      * ctrl[b]
       + 3*(1-u)^2*u  * ctrl[b+1]
       + 3*u^2*(1-u)  * ctrl[b+2]
       + u^3          * ctrl[b+3];              /* DAT_1404deed8 = 3.0 */
    curve[i] = min(v, vatr[0x70]);
}
```

**28 = 9 段 × 3 + 1**,标准分段三次 Bézier;节点和控制点都是 uint16 / 1024,
量纲就是 log2 亮度(0 ~ 13)。

### 5.1 曲线来自 ARW(逐指令确认)

`FUN_1401887b0` 末尾(`0x140188ae9`):

```asm
LEA RBX,[R14 + 0x1106]      ; R14 = calib
LEA RDI,[R14 + 0x10f2]
MOV qword ptr [RSP+0x28],RBX   ; 第 6 参 = ctrl
MOV qword ptr [RSP+0x20],RDI   ; 第 5 参 = knots
MOVZX R9D,byte ptr [R14+0x10f0]; 第 4 参 = flag
MOV EDX,R12D                   ; 第 2 参 = level
CALL 0x14018ad50
```

而 `FUN_14015f540`(标定解析器)里:

| calib 偏移 | SR2 标签 | 内容 |
|---|---|---|
| `+0x10f2` | **`0x781b`** | 10 × uint16 —— Bézier **节点** |
| `+0x1106` | **`0x781c`** | 28 × uint16 —— Bézier **控制点** |
| `+0x10f0` | (推导) | `0x781b` 十项全零 → 0,否则 1 |

**所以「Auto 档位由引擎按画面自行决定」这条要修正:
决定的是相机,结果以曲线形式写进了 RAW,引擎照搬。**
离线复刻只需要能解出 `0x781b`/`0x781c`,不必重建判级逻辑。

### 5.2 level 怎么定(`FUN_140175830`,`0x140175d21`)

```c
if (st[0x238] == 1) {                    /* 编辑参数 0x8022 == 1  → Auto */
    level = (calib[0x10f0] == 0) ? 5 : -1;
} else {
    level = st[0x23c];                   /* 编辑参数 0x8023 → 手动 DRO 级 */

```
即:Auto 且 RAW 里有曲线 → 用 RAW 的;Auto 但 RAW 里没有 → 回落到 `level = 5`
(在预设 #0 和 #1 之间插值,u = 0.5)。
