# 35f1c0 — 判据函数 vt[0xb0]：H/(H+V) 归一化

函数体 0x14035f1c0..0x14035f334（`ret`）。文件后面 0x14035f340 起是另一个函数，
不属于本函数（但见 §4 的旁证）。

## 1 签名

```
void __fastcall crit(void* this /*rcx，未用*/,
                     Plane* dst   /*rdx → r13*/,
                     Plane* aggH  /*r8  → r12*/,
                     Plane* aggV  /*r9  → r15*/,
                     void*  a5    /*[rsp+0x28]，未用（运行时为 0）*/,
                     Roi*   roi   /*[rsp+0x30] → rdi*/,
                     const float* P /*[rsp+0x38] → r14*/,
                     void*  a8    /*[rsp+0x40]，未用（运行时为 0）*/)
```

推导：入口 `push rdi/r12/r13/r15`（4×8 = 0x20），故 `[rsp+0x50]` = 原 `[rsp+0x30]`
= 第 6 参 = roi（用 +8/+0xc/+0x10/+0x14，且退出时往 +0 写 vptr），
`[rsp+0x58]` = 原 `[rsp+0x38]` = 第 7 参 = 参数块。

**dst 既是输入也是输出（in-place）**：读 `dst[y][x]` 当作垂直代价 V，再把结果写回同一格。

## 2 循环结构

```
r11d = y = roi.y0;  while (y < roi.y1)          // 外层，步进 1
    ecx = x = roi.x0;  while (x < roi.x1)       // 内层，步进 1（指针 +4）
```
每行开头重取 `aggH.data / aggV.data / dst.data` 与各自的 `height/stride`，
行索引越界（`y >= plane.height`）或 `data == NULL` 时把该行基址置 0（不是跳过，
会直接解引用 0 + x*4；实际调用里不会发生）。
内层循环每次迭代都重读 `roi.x1`（`[rdi+0x10]`）。

## 3 抽头几何

纯逐点，1×1。三条平面同坐标 (x, y)，无邻域。
指针技巧：`rax = dstRow + x0*4`，`rbx = aggHRow − dstRow`，于是 `[rax+rbx]` = aggH 同点。

## 4 常量

| VA | 数值 | 角色 |
|---|---|---|
| 0x1404deb28 | 0.5f | 分母 `A+B` 不 > 0 时的兜底输出 |
| （xorps xmm5） | 0.0f | **`max` 的初值** —— 之前没回溯出来的那个，就是常数 0 |
| 0x140466678 | — | 退出时写进 `roi[0]` 的 vptr（35f510 / 361950 都写同一个） |

参数块（r14）只用到三个 float，偏移 **+0 / +4 / +8**：

| 偏移 | 记号 | 角色 |
|---|---|---|
| +0 | P0 | 从 aggH 里减掉的阈值（死区） |
| +4 | P1 | 从 dst（V 代价）里减掉的阈值 |
| +8 | P2 | 同时加到 A 和 B 上的正则项 ε |

⚠ **与 `{uint8 flag; float p[11]}` 布局不符**：本函数不读 flag 字节，也不做
`+1/+5/+9` 的错位访问。361950 与 0x35f340 读同类块时用的是 `[rdi+0]=flag`、
`[rdi+1]=p[0]`、`[rdi+5]=p[1]`… 所以要么 35f1c0 收到的第 7 参是 `&blk.p[0]`
（= 块地址 +1），要么它收到的是另一种「无 flag、三个 float」的块。
运行时两个块（0x1405a8b28 / 0x1405a8b48）在这三个位置**都是 0**，两种解释数值上
不可区分，故此处只按反汇编事实记 +0/+4/+8。

另：笔记里「0x1405a8b48 第 9 个 float = 8.0」与「0x1405a8b68 的 p[0] = 8.0」指向
同一个地址 0x1405a8b69 —— 块的实际跨距是 **0x20 字节**，不是 45 字节，
「11 个 float」是越界读到下一个块了。

## 5 算式

```c
const float EPS0 = 0.0f;      // xorps xmm5, xmm5

for (y = roi.y0; y < roi.y1; ++y)
  for (x = roi.x0; x < roi.x1; ++x) {
      float A = fmaxf(0.0f, aggH[y][x] - P[0]) + P[2];   // 水平侧
      float B = fmaxf(0.0f, dst [y][x] - P[1]) + P[2];   // 垂直侧（dst 原值）
      float S = B + A;                                    // 加法顺序如反汇编
      dst[y][x] = (0.0f < S) ? (A / S) : 0.5f;            // comiss 0,S; jb
  }
roi[0] = (void*)0x140466678;
```

`comiss xmm5, xmm3` + `jb` ⇒ 只有 `S > 0` 才做除法；`S == 0`、`S < 0`
或 `S` 是 NaN 都返回 0.5。

**运行时两次调用的参数块全 0**，所以实际执行的是：

```c
dst[y][x] = max(0,aggH) / (max(0,aggH) + max(0,dst_old));   // 两者皆 0 → 0.5
```

## 6 调用

叶函数，无 call。

## 7 一句话定性

逐点把「水平聚合代价」归一化成 `H/(H+V)` 的 0..1 方向权重并原地写回 dst；
`max` 的初值是 0，`P[0]/P[1]` 是各自的死区阈值、`P[2]` 是防 0/0 的 ε，
分母非正时输出 0.5。

### 附：0x14035f340（`ret` 之后的下一个函数，非本函数）

3×3（9 抽头）平均绝对偏差：对 `[rdx+0]..[rdx+0x20]` 九个 float 累加
`|xmm3 − t_i|`（全程 double，掩码 0x1404e02b0），再 `/9.0`（0x140466970），
然后 `- p[1]`（`[rax+5]`）、`* p[0]`（`[rax+1]`），再与 0.99609375（0x140466964）
比较。**这是 `{uint8 flag; float p[…]}` 布局的第二处旁证。**
