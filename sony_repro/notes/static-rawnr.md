# RawNR(机内降噪)静态反编译

* 反编译产物:`tools/rawnr_decomp.c`;参考实现:`tools/rawnr_ref.py`
* **没有叫 `ZcTaskRawNR` 的类。** 全二进制里这一族是:

| 类 | exec RVA | 大小 | 备注 |
|---|---|---|---|
| `ZcTaskRawNRSIMD` | `0x39fab0` | 4324 | **执行路径上的那个**(每 tile 一次,35 次) |
| `ZcTaskRawNRHalf` | `0x384cb0` | 2850 | **标量实现,已完整解出** ← 本文主体 |
| `ZcTaskRawNrPBX` | `0x3b4bb0` | 2950 | 另一实现 |
| `ZcTaskYNR` | `0x39d230` | 865 | 亮度 NR |
| `ZcTaskBSNR_Y` / `ZcTaskSIMDBSNR_Y` | `0x39d050` / `0x39bf40` | 359 / — | |

> ⚠️ `ZcTaskRawNRSIMD` 的 exec 与 `ZcTaskSIMDSpica` 的 vtable 槽 `+0x110`
> 是**同一个函数** `0x39fab0`。两个类共用这段代码,读的时候别搞混。

## 0. 先纠正三条旧结论

这份笔记早先写的三件事都是错的,现在有反汇编为据:

1. **不是「多分辨率金字塔/小波子带收缩」。** 没有金字塔,没有小波,没有多分辨率。
   就是一次 3×3 二项式低通/细节拆分,加一个 5×5 的 sigma 滤波。
2. **`FUN_140385af0` 不是「正变换」,`FUN_1403857e0` 不是「逆变换」。** 前者是
   **脉冲钳位**,后者才是整台降噪器。两个都已读完(§1、§2)。
3. **`RawNRHalf` 与 `RawNRSIMD` 不同构。** 旧笔记把这条列为「未验证的假定」,
   现在验了 —— **不成立**,见 §5。名字里的 "Half" 也不是「半分辨率」。

## 1. `0x385af0` —— 脉冲钳位(每平面第一步)

```c
for each pixel:
    n[4] = {上, 左, 右, 下};
    sort(n);                       /* call 0x384850,四元排序 */
    dst = clamp(center, n[1], n[2]);
```

把中心像素钳进四邻域的**中间两位**之间。没有任何 sigma 余量 —— 这比 llr 的
`_clamp_impulses`(钳进 `min - kσ .. max + kσ`)激进得多。它清的是最细尺度上的
孤立点(坏点、宇宙射线),而不是噪声本身;噪声交给第二步。

## 2. `0x3857e0` —— 降噪器本体

签名(Ghidra 只认出前四个寄存器参数,后四个在栈上):

```c
filter(this, src, dst, rect, int OFFSET, int GAIN, int LIMIT, int32_t *thr)
/*                          [rsp+0x90]  [+0x98]   [+0xa0]    [+0xa8]      */
```

逐像素:

```c
hp  = 12*c - 2*(上+下+左+右) - (四个对角);
d   = hp / 16;                          /* cdq;and 0xf;add;sar 4 —— 向零取整 */
lo  = c - d;                            /* == 3x3 二项式核 [[1,2,1],[2,4,2],[1,2,1]]/16 */

ref = clamp(lo + OFFSET, 0, 0x7fff);    /* 既是查表下标,也是邻域比较的基准 */
t   = thr[ref];

sum = 0; n = 0;
for (dy = -2; dy <= 2; ++dy)
  for (dx = -2; dx <= 2; ++dx) {
      if (dx == 0 || dy == 0) continue;             /* 穿过中心的行与列都不取 */
      v = src[y+dy][x+dx];
      if (abs(v - ref) < t) { sum += v; ++n; }
  }
mean = (ref + sum) / (n + 1);

dst = clamp(mean + clamp(d * GAIN >> 8, -LIMIT, LIMIT) - OFFSET, 0, 0x3fff);
```

三处值得单独记:

* **参考值用低通 `lo`,不是中心像素 `c`。** 拿噪声像素自己当比较基准,阈值判断
  本身就被噪声带偏了。这是整套手法里最该抄的一条。
* **支撑集是 16 个点**(`dy, dx ∈ {-2,-1,1,2}`),穿过中心的整行整列都不取。
  反汇编里 `dx==0` 被编译期消掉,`dy==0` 留下一条运行期 `test r9d,r9d; je`。
* **细节是被放大后补回去的。** `GAIN` 实测 452~480,即 ×1.77(§3),`LIMIT`
  是随之而来的**光晕限幅** —— 没有它,边缘处 `d*GAIN` 会大幅过冲。所以这一支
  同时是降噪和锐化:sigma 滤波清掉 3×3 与 5×5 之间那一段频带,最细的一段
  (已被第一步清过)原样放大送回。

## 3. 参数:全部来自 ARW,且**逐平面**

`0x384cb0` 对平面 0/1/2 各调一次,参数取自 calib:

| plane | OFFSET | GAIN | LIMIT | 阈值强度 |
|---|---|---|---|---|
| 0 | `c[0x1018] - c[0x1020]` | `c[0x1048]` | `c[0x1054]` | `c[0x103c]` |
| 1 | `c[0x1018] - c[0x1028] - c[0x101c]` | `c[0x104c]` | `c[0x1058]` | `c[0x1040]` |
| 2 | `c[0x1018] - c[0x1024]` | `c[0x1050]` | `c[0x105c]` | `c[0x1044]` |

阈值表(32768 项,`v` 是**局部低通电平**):

```c
base  = strength * c[0x1034] * 3 >> 8;
slope = strength * c[0x1038] * 3 >> 8;
thr[v] = clamp(((clamp(v, c[0x102c], c[0x1030]) - c[0x102c]) * slope >> 12) + base,
               0, 0x3fff);
```

`DAT_140559490 < 2` 走标量建表,否则走 SSE4,**数学完全一样**。

**tag → calib 的映射是在 `0x1611a5` 起的解析器里逐条读出来的**,一 tag 一槽,
**没有钳位**:

| calib | tag | | calib | tag |
|---|---|---|---|---|
| `+0x1018..+0x1028` | `0x78c0..0x78c4` | | `+0x103c..+0x1044` | `0x78c9..0x78cb`(三平面强度) |
| `+0x102c` | `0x78c5` 电平下限 | | `+0x1048..+0x1050` | `0x78cc..0x78ce`(三平面 GAIN) |
| `+0x1030` | `0x78c6` 电平上限 | | `+0x1054..+0x105c` | `0x78cf..0x78d1`(三平面 LIMIT) |
| `+0x1034` | `0x78c7` 基准系数 | | `+0x1060` | ← `0x104c` 经 `>256` 分支,**Sharpness 用** |
| `+0x1038` | `0x78c8` 斜率系数 | | | |

> 旧笔记写「`0x1048` 被 `0x78cd > 256` 时钳到 `0x100`」—— **读错了**。
> `0x161299` 那句 `cmp ecx,0x100` 比的是 `calib[0x104c]`(tag `0x78cd`),
> 走的是 **Sharpness** 那条分支,和 `0x1048` 无关。`sharpness.py` 里独立验证过的
> `SHARPNESS_CALIB_TAG = 0x78CD` / `SHARPNESS_CALIB_BASE = 0x100` 正好对上,
> 互为佐证。所以 GAIN 是标签原值,细节确实被放大 1.77 倍。

实测五张(`tools/rawnr_model.py`):

| ISO | lo | hi | 基准 | 斜率 | strength | GAIN | LIMIT | 阈值 @ 电平 0 / 2048+ |
|---|---|---|---|---|---|---|---|---|
| 100 | 0 | 2048 | 10 | 72 | 32 | 480 | 1023 | 3 → 16 |
| 160 | 0 | 2048 | 11 | 77 | 32 | 458 | 1023 | 4 → 18 |
| 200 | 0 | 2048 | 12 | 79 | 32 | 452 | 1023 | 4 → 18 |
| 1250 | 0 | 2560 | 30 | 183 | 32 | 268 | 1023 | 11 → 53 |

**GAIN 随 ISO 往回收**(480 → 268,而 256 就是原样)。这独立佐证了它的语义:
低感放大细节等于锐化,高感放大细节等于放大噪声,所以高感几乎不放大。
阈值同时往上走(3→11 / 16→53),两者方向相反,合起来才是「高感多降噪、少锐化」。

三个平面的 strength 在这五张里恒等,所以还分不出它们各自对应什么。
`OFFSET` 在 plane 0/2 上是 0(512−512),plane 1 上是 −512 —— 这一项的语义**未解**,
见 §6。

## 5. `RawNRHalf` 与 `RawNRSIMD` **不同构**(旧假定被推翻)

三条独立证据:

1. **不共用代码。** `xref` 显示 `0x385af0` / `0x3857e0` 的调用者**只有** `0x384cb0`。
   `RawNRSIMD` 调的是自己的一套核:`0x3a0c30`(3789)/ `0x3a1b00`(3048)/
   `0x3a26f0` / `0x3a2aa0`。
2. **数域不同。** Half 是 16 位整数 + 32768 项查表;SIMD 那几个核里是
   `vmulss` / `vbroadcastss` / `vcvtsi2ss`,**float32 AVX2**。
3. **支撑集不同。** Half 的循环从 `-2` 起(`mov r9d,0xfffffffe`);SIMD 核里的
   循环初值是 `0xfffffffb`(−5)和 `0xfffffffa`(−6)。这也和 §7.13 的实测对得上 ——
   5×5 线性拟合只解释 70%,9×9 才到 88%,本来就说明支撑比 5×5 宽。

## 5.1 但两者**共用同一套噪声模型**(已从进程里验证)

`RawNRSIMD::exec` 里只引用了 `0x1018..0x1028`,没碰阈值那两组 —— 因为表不是在 exec
里建的。`rawnr_probe.py` 把它抓了出来:`task->[0x68]` 指向的参数块,
`+0xd0 + k*0x20000` 是第 k 张 32768 项 int32 表(共六张),`+0xc0000` 起是标量参数。

抓到的表与 §3 那套公式从 ARW 标签算出的**逐项一致**(ISO 1250:11/45/53;
ISO 100:3/16/16)。所以 §3 的噪声模型对**实际渲染路径**也成立,
`apps/worker` 的 `sony/rawnr.py` 据此落地。

参数块里还有 `+0xc00e8/ec/f0 = 256`(细节增益)和 `+0xc00f4/f8/fc = 1023`(限幅),
角色与 §3 的 GAIN / LIMIT 完全对应。**但增益恒为 256(=原样)**,而标签在两张图上
是 480 / 268 —— SIMD 路径**不放大细节**。两张的标签都 >256,所以还分不清它是常量
还是 `min(tag, 0x100)`。tbl3/4/5 是常数 512,用途未知。

另有一段按 ISO 的强度插值(`0x39fb4c..0x39fbbe`):ISO ≤400 → 0.4,ISO ≥1600 → 1.0,
中间线性。这是「ISO 100 上它几乎什么都没做」的直接原因。

## 5.2 它跑在马赛克上,逐相位;§2 的算子形状对它**不成立**

两条独立证据:抓到的入口平面里,相隔奇数的差 std 是 388,相隔偶数的只有 84
(四相位均值 1001/1208/1211/721,典型 RGGB);`0x3a0ba0` 分配的 16 个 float32
缓冲区尺寸全是 **567×567 = 1134/2**,**没有**逐级减半的金字塔。

拿抓到的表 + 增益 256 + 限幅 1023,逐相位跑 §2 的算子,试遍参考值、半径 1..4、
是否跳过中心行列 —— **最好一档只解释掉 12.8%**,多数比什么都不做还差;
而同一份 delta 用 9×9 线性核能解释 85%。**所以它不是「Half 换个半径」。**
真正的形状见 §5.3。那批候选扫描已被 `rawnr_simd.py` 取代并从 `rawnr_fit.py` 删掉,
该工具现在只留线性核那半边(量支撑集有多大)。

> ⚠️ 用 `tile_dump.py` 的结果**必须按有效矩形裁剪**(`task+0x30`,这批是
> `[16,16,1118,1118]`)。输出是新分配的缓冲区,矩形外从没写过,那圈数据 |d| 有 800 上下,
> 不裁的话统计和拟合会被整个带偏。

## 5.3 但**算子形状是同一族**:SIMD 的分析核与 §2 逐字相同

§5.2 的否定只针对「Half 的完整算子」。把 AVX2 读开之后,分析那一步是**同一个东西**
(详见 PIPELINE.md §7.13.3,复刻在 `tools/rawnr_simd.py`):

* `0x3a2aa0`(R/B):`d = (12c − 2*N4 − diag)/16`,`ref = clamp(c − d + OFFSET, 0, 32767)`
  —— 与 §2 **逐字相同**,只是 float32。常量 12.0 / 0.0625 / 32767.0 就摆在那里。
* `0x3a26f0`(绿):同平面那 12 个抽头 + 另一绿平面 4 个 ×3,合 24,`d = (24c − Σ)/28`。
* `0x3a1b00`(R/B 滤波)的收尾与 §2 **逐字相同**:
  `out = clamp(mean + clamp(d*gain/256, ±limit) − OFFSET, 0, 16383)`。

差别在中间:比较基准是「中心低通与其 3×3 均值按 `tbl3/1024` 混合」,支撑是
**间距 2 的 5×5**(行 `y-4,y-2,y,y+2,y+4`,读自 `0x3a1c87..0x3a1d13`),
而且**抽头取的是 ref 低通,不是原图**。这三条就是 §5.2 里那套候选对不上的原因。

实测(`rawnr_simd.py --verify`):**analysis 逐位 100% 相同,filt 99.9677%,
端到端解释掉 100.00%**。剩下 60 点(0.03%)是一个抽头的取舍不同 —— float32 比
float64 更贴引擎(60 vs 3170 点),两种精度下被接纳的抽头数一致,而这些点被接纳的
抽头数中位只有 6(全体 21),误差量级正好等于一个抽头进出的幅度。

三个 OFFSET 的来源也追到了(`0x3a0018..0x3a0041`),与 §3 逐条相同:
`c[0x1018]−c[0x1020]` = 0(R/B 之一)、`c[0x1018]−c[0x1028]−c[0x101c]` = −512(绿)、
`c[0x1018]−c[0x1024]` = 0(R/B 之二)。

> ⚠️ **别跨工具按序号配对 tile。** tile 是多线程并行跑的,同一张图连抓两次,
> 「第 0 次内核调用」的平面尺寸都能不一样;`0x39fab0` 又和 `ZcTaskSIMDSpica` 共用。
> 早先据此得出「R 相位只有 65.6%,缺口在分析那一侧」,**是拿错了 tile,已推翻**。

## 6. 没解出的部分

**绿色滤波核 `0x3a0c30`(3789 字节)的抽头集**(详见 PIPELINE.md §7.13.4)。
骨架已读出且与 R/B 同构 —— 25 个抽头、混合基准、同样的收尾 —— 但两处不同:
邻域均值的系数是 `1/25`(不是 `1/9`),输出钳位是 `262143`(不是 `16383`)。
参数实抓为 `limit=1023, gain=256, offset=−512, flags=0,−1`。

套 R/B 的几何只到 **40.9%**,所以那 25 个抽头**必然包含另一个绿平面**。
回归能确认「是等权平均」(系数和 0.9999)、自身平面的显著项全在偶数偏移上,
但定不下完整抽头集 —— 中心项被阈值选择抬高到 0.37,而且核把抽头值预载进寄存器,
只看内存操作数是不够的,得逐条回溯寄存器。

绿的**分析**核 `0x3a26f0` 已解(§5.3)。
2. **`OFFSET` 的语义。** 它同时被加进查表下标和邻域比较的基准,而邻居值没有加。
   plane 0/2 上它是 0,所以无影响;plane 1 上是 −512,那里会有系统性直流偏差 ——
   要么 plane 1 的数据本来就带 +512 基座,要么我读错了。五张样本里
   `0x78c0..0x78c4` 全等于 512,分辨不出来。
3. **三个平面各是什么。** RawNR 跑在 `TileDiv` 之后,平面的色彩含义没查。
4. `ZcTaskBSNR_Y`(`0x39d050`)、`ZcTaskRawNrPBX`(`0x3b4bb0`)—— 没跑过,也没读。
   `ZcTaskYNR`(`0x39d230`)**会跑**,见 §7 —— 只是默认设置下不跑。

## 7. 降噪的 UI 模型:滑块落在哪(实测)

**为什么之前以为 YNR 不跑。** 把 Edit.exe spawn 起来等着,200 秒里只有
`ZcTaskRawNRSIMD` 进过,于是记成「没跑过」。那是错的 —— 默认设置下降噪那几级
是关的。attach 到用户正在操作的实例、由人去动界面上的滑块,`ZcTaskYNR` 立刻上线。
**这类「某任务从不执行」的结论,必须在把相关控件真正打开之后才成立。**

UI 侧的符号在二进制里(`GfDocument` 的四个虚函数):

    ?ModifyNrAmount@GfDocument@@UEAAIHW4RenderBehavior@sony_granada@@...
    ?ModifyNrChroma@GfDocument@@...          同签名,第一个参数是 int
    ?ModifyNrEdge@GfDocument@@...            同签名
    ?ModifyNrParams@GfDocument@@UEAAIW4NrOption@sony_granada@@...

`NrOption` 是枚举,自动/手动应该就在它上面。**但这四个串没有任何代码引用** ——
`.data` 里的链接器元数据,qword 扫描和 RIP 相对扫描(`xref_va.py`)都是 0 处。
所以走不通,只能从引擎侧看参数。

引擎侧(`task->[0x68]` 那块,与 §3 同一处)实测有**两组独立**的东西在动:

| 位置 | 基线 | 变化后 | 是什么 |
|---|---|---|---|
| `tbl0..2`(阈值表) | @2048 = 51 | ×2 → 103,或整体 → 0 | 噪声阈值,整条曲线被缩放 |
| `tbl3..5`(混合权重) | @2048 = 512 | → 1024 | |
| `+0xc00e8/ec/f0` | 0 | 256 | GAIN,逐平面,8.8 定点 |
| `+0xc00f4/f8/fc` | 1023 | 8184 | LIMIT,逐平面 |

两组能分别改变,互不牵连。GAIN/LIMIT 那一组**在 RawNRSIMD 和 YNR 上同时变**,
说明这两级共用同一份参数块。

**基线表就是相机自己那条曲线**:DSC03036 的机内模型是 `base=13 slope=78`,
算出 `thr(2048) = ((2048*78)>>12)+13 = 52`,实测基线 51。滑块是在它上面乘系数,
不是另起一套。这与 §5.1 从进程里读表得到的结论一致,但这次是从**用户可见的控件**
这一端确认的。

### 7.1 面板上有**三个**控件,不是两个

手动全局量 / 色彩降噪 / 边缘降噪,UI 上都是 `0..100`、默认 `50`。正好对上二进制里的
`ModifyNrAmount` / `ModifyNrChroma` / `ModifyNrEdge`。

**内部值不是 UI 值**:`+0xc0124` 存的是 `t = (UI − 50) × 2`,即 `−100..+100`,
默认 50 落在中性的 0 上。单滑块扫描(0/25/50/75/100)实测:

| UI | t | GAIN `+0xc00e8/ec/f0` | LIMIT `+0xc00f4/f8/fc` |
|---|---|---|---|
| 0 | −100 | 256 | 8184 |
| 25 | −50 | 252 | 4603 |
| 50 | 0 | **249** | **1023** |
| 75 | +50 | 124 | 1023 |
| 100 | +100 | 0 | 1023 |

中性位的 249 / 1023 **就是这张片的机内标签**(`0x78CC..0x78CE` / `0x78CF..0x78D1`,
`rawnr_model.py` 读得到)。所以滑块是在相机自己的值上双向调制:

    t = (UI − 50) * 2
    t >= 0:  GAIN = base_gain * (1 - t/100)                     LIMIT = base_limit
    t <  0:  GAIN = base_gain + (256 - base_gain) * (-t)/100
             LIMIT = base_limit + (8*base_limit - base_limit) * (-t)/100

全部**逐位吻合**(向零截断):`t=−50 → 249+7×0.5 = 252.5 → 252`;
`1023+7161×0.5 = 4603.5 → 4603`;`t=+50 → 249×0.5 = 124.5 → 124`。

语义与 §2 的公式对得上 —— `boost = clamp(d*gain/256, ±limit)` 是降噪后**往回补多少
细节**。UI 0 = GAIN 拉满 256、限幅放宽 8 倍 = 尽量保边;UI 100 = GAIN 0 = 一点不补
= 尽量平滑。所以「边缘降噪」调的是细节回注,不是另一个滤波器。

同一份参数在 `RawNRSIMD` / `ChromaSuppres` / `SSCS` / `SIMDSpica` 上**同时变**,
再次印证这些阶段共用一个参数块。

### 7.2 色彩降噪:另一个字段,而且**只有上半边有效**

滑块值在 `+0xc0120`(边缘是 `+0xc0124`,相邻但各是各的),驱动另外三个字段。
UI 档位也不同 —— 色彩吸附到 10 的倍数(25 会跳成 20,75 跳成 70),边缘接受 25/75。

| UI | t = (UI−50)×2 | `+0xc010c` | `+0xc0110` | `+0xc0114` |
|---|---|---|---|---|
| 0 | −100 | 0 | 0 | 0 |
| 20 | −60 | 0 | 0 | 0 |
| 50 | 0 | 0 | 0 | 0 |
| 70 | +40 | 2000 | 2000 | 600 |
| 100 | +100 | 2500 | 2500 | 1500 |

**负半边是死区。** UI 0..50 上三个字段恒为 0 —— 「比默认更弱的色彩降噪」在这块参数
里没有表达,与边缘降噪的双向调制完全不同。回程(100 → 70 → 50)复现了去程的值,
不是抖动。

`+0xc0114 = 15 * t`(t>0),两点都精确。`+0xc010c` 与 `+0xc0110` 恒等(大概是 Cb/Cr
两路),但过 (40,2000) 与 (100,2500) 的直线截距是 1666.67,不像真值 —— 中间应有拐点,
两点定不下来,要在上半边加密采样(50/60/70/80/90/100)。
