|---|---|---|---|

## 0. 算法形态

**多分辨率(金字塔/小波)子带收缩。** 三个平面各走一遍:

```c
for (p = 0; p < 3; ++p) {
    analysis(this, src.plane[p], work, rect);        /* FUN_140385af0 */

    /* 建一张 32768 项的阈值表 */
    base  = calib[STRENGTH[p]] * calib[0x1034] * 3 >> 8;
    slope = calib[STRENGTH[p]] * calib[0x1038] * 3 >> 8;
    for (v = 0; v < 0x8000; ++v) {
        x      = clamp(v, calib[0x102c], calib[0x1030]);
        thr[v] = clamp( ((x - calib[0x102c]) * slope >> 12) + base, 0, 0x3fff );
    }

    synthesis(this, work, dst.plane[p], rect);       /* FUN_1403857e0,用 thr */
}
task->planes = dst;                                   /* FUN_14016b640 */
```

`STRENGTH[0..2] = 0x103c / 0x1040 / 0x1044`。

阈值是**关于局部信号电平的分段线性函数**:低于 `calib[0x102c]` 恒为 `base`,
高于 `calib[0x1030]` 恒为 `base + (0x1030-0x102c)*slope>>12`,中间线性 ——
即「亮处允许更大的噪声阈值」,标准的散粒噪声模型近似。

`DAT_140559490 < 2` 时走标量建表,否则走 SSE4 建表,**数学完全一样**
(SSE 那支只是把 clamp 和 `pmulld` 向量化)。

## 1. 参数全部来自 ARW(`FUN_14015f540`)

| calib 偏移 | SR2 标签 | 用途 |
|---|---|---|
| `+0x102c` | **`0x78c5`** | 电平 clamp 下限 |
| `+0x1030` | **`0x78c6`** | 电平 clamp 上限 |
| `+0x1034` | **`0x78c7`** | 阈值基准系数 |
| `+0x1038` | **`0x78c8`** | 阈值斜率系数 |
| `+0x103c` | **`0x78c9`** | plane 0 强度 |
| `+0x1040` | **`0x78ca`** | plane 1 强度 |
| `+0x1044` | **`0x78cb`** | plane 2 强度 |
| `+0x1048` | `0x78cc` | (被 `0x78cd > 256` 时钳到 0x100) |
| `+0x104c` | `0x78cd` | → `calib[0x1060]`,**Sharpness 用**,见 `static-sharpness.md` |
| `+0x1050` | `0x78ce` | 未追 |

同一批还有 `+0x1018 .. +0x1028` ← `0x78c0 .. 0x78c4`,没读用途。

**这批系数是逐图的**(随 ISO/机型由相机写入),所以「照搬」是可行的:
不需要自己建噪声模型,直接读标签。

## 2. 「是否可离线复现」——答案:**参数可以照搬,变换本身要重写**

* ✅ 阈值表的生成逻辑完全解出,输入全是 ARW 标签,可以一比一复刻。
* ❌ `FUN_140385af0`(analysis,正变换)与 `FUN_1403857e0`(synthesis,逆变换)
  **我没有反编译**。这两个是真正的算法核心 —— 到底是 Haar / 5-3 提升小波 /
  高斯金字塔,几层,子带怎么排,收缩函数是硬阈值还是软阈值,全部未知。
* 因此现在的结论是:**形态清楚(子带阈值收缩 + ARW 里的噪声模型),
  但还不能写出可运行的复刻。** 要继续得再啃这两个函数,
  它们不在 `rawnr_decomp.c` 的深度 0 里已经导出了(见文件末尾两段)。

## 3. 对用户那个问题的直接回答

> 「如果 Edit 里有实现且方便照搬就照搬」

* **参数照搬:立刻可做**,`0x78c5..0x78cb` 七个 uint32,配上 §0 的公式
  就能得到「每个平面、每个信号电平允许多大噪声」这条曲线。
  这本身就是一份免费的、逐图的噪声模型,拿去驱动任何现成的降噪器都比拍脑袋强。
* **算法照搬:不方便。** 变换核未解,而且降噪与后面的 ITP / Spica / Sharpness
  是串在一起调的(见 `static-itp-spica.md`),单独接一段 NR 未必能改善
  当前 12.5/255 的残差 —— 那份残差模糊后掉一半,主因更可能是**没有锐化**
  而不是**没有降噪**。建议优先级排在 Sharpness + Spica 之后。

## 4. 没解出的部分

1. `FUN_140385af0` / `FUN_1403857e0` 的变换核(见 §2)。
2. `ZcTaskYNR`(`0x39d230`)、`ZcTaskBSNR_Y`(`0x39d050`)—— 都没跑过,也没读。
3. `RawNRSIMD`(实际在跑的那个,`0x39fab0`)与 `RawNRHalf` 的差异没有逐行比对;
   我是**假定**它们同构才拿 Half 当规范的。这个假定**没有验证**,
   与 SSCS/ITP 那几次「标量孪生版逐行对应」的先例不同 ——
   RawNRHalf 名字里的 "Half" 也可能意味着半分辨率处理。**用之前请动态确认。**
