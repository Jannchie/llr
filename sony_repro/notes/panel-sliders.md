# Edit 面板的创意外观滑块 —— 量纲、落点与机内档位的换算（动态分析，2026-09-11）

**结论：Edit 面板上创意外观那一组滑块（对比度/高光/阴影/白色/黑色/褪色，以及
色相/饱和度、清晰）全部是 ±100（褪色、清晰 0..100），引擎的编辑参数结构体
`opts` 里存的就是面板值；机内 −9..+9 档在装载时换算成面板值。llr 原先按机内
档位做 UI，所以"范围对不上、缺白色/黑色/色相"。三个影调滑块的换算是
`面板 / 5`，对引擎 tone LUT **逐位 0 差**（±100 全程，含两两叠加）。**

## 2. 落在 `opts` 的哪个偏移

`tools/opts_locate.py`：改一张 ARW 的机内 tag（`patch_slider` 的做法）→ spawn
Edit → 钩 `ZcTaskSIMDSharpness` 拿 `opts = *(a[2]+8)` 整段 → 与基线 diff。
`tools/panel_sweep.py`：attach 到跑着的 Edit，用键盘消息拨面板滑块，再从
YGamma 的钩子里读同一段。

| 面板 | `opts` 偏移 | 机内 tag → 面板 |
|---|---|---|
| 饱和度 | `+0x1fc` | `SATURATION_STEPS[档]`：9 → 55（就是 PIPELINE §7 的"引擎内部值"） |
| 对比度 | `+0x200` | ×5 |
| 色相 | `+0x204` | 机内无 |
| 黑色 (bl) | `+0x2ac` | 机内无 |
| 白色 (wl) | `+0x2b0` | 机内无 |
| 高光 | `+0x2b4` | ×5 |
| 阴影 | `+0x2b8` | ×5 |
| 褪色 | `+0x2bc` | ×10 |
| 清晰 | `+0x2c0` | ×10（§7.9.1 的 `clr`，就是面板值） |
| 锐度范围 | `+0x2c4` | 面板原值（初值 50） |

`0x2ac/0x2b0` 正是 `slider_probe.py` 一直在读的 YGamma `bl/wl`，之前所有样本
都是 0 —— 因为相机根本没有这两个滑块。

## 3. 三个影调滑块：`面板 / 5`，family 表外**线性外推**

`panel_sweep.py` 抓 MainGamma 出口那张 32768 项 tone LUT（`lv+0x118f6`），
对 llr `tone.apply_tuning(base, highlights=面板/5, ...)`（`/tmp/fit*.py` 那几个
拟合脚本的整理版在 `tools/panel_fit.py`）：

| 面板 | 0 | ±30 | ±45 | ±50 | 46/48/52/54/58/65 | ±100 | 对比度 +100 & 高光 +100 |
|---|---|---|---|---|---|---|---|
| max\|diff\| /16384 | 0 | 0 | 0 | 0 | 0 | 0（外推）/ 179~311（钳位） | 0（gain 58） |

- 增益 = 18 + 对比度/5 ± (高光/5 或 阴影/5)，同 tone.py；面板 ±100 → gain −2 / 38。
- **引擎在 family 的 0 行以下、36 行以上沿最后一对行线性外推**，不是钳位在 35。
  llr `tone._segment` 已改成外推（`TUNE_GAIN_ROWS = 37`）。
- 中间一度看到 60..90 段"差 0.2 档"，是探针的按键/抓取错位一格（单键时多按一次，
  抓到的是前一档的渲染），修好工具后全部归零。**扫描工具的 arm 必须在最后一次
  按键之前、前面按键的渲染跑完之后。**

## 4. 其它滑块

- **褪色**：索引 = 面板/10。contrast 在表项之间线性插值（面板 5 → 16448 =
  (17280+15616)/2），表外线性外推（面板 100 → 9472 = 10112 − 640）；**pivot 不插值，
  面板 5 已经取到表 [1] 的 10624**（取上一项）。索引 0..1 之间的更细规则未测
  （Edit 后来一直崩，见 §6）。
- **饱和度**：面板值就是 `1+v/100` 里的 v。RGB2YCC 钩子 `rsp+0x38` 那八个 short
  **不随面板饱和度变**（它们是除法之前的值），所以这次没能在 ±100 端复核"两段相消"；
  −100 按 ×0 处理（全灰）。
- **白色/黑色**：`bl/wl` 原值进 YGamma，公式在 `chroma.py` 头注释（反汇编所得）：
  `black_int = −trunc(bl/4)`，`black = black_int·32767/512`，
  `scale = 512/((512−wl)−black_int)`，`Y' = ((lut[Y]−black)·scale−pivot)·contrast+pivot`。
  **未做 tile 级验证**。
- **色相**：`ZcTaskHueSaturation`（PIPELINE §7）：角度 = 面板 × 0.7°（正）/ 0.35°（负），
  旋转 (Cb, Cr)，输出角量化到 512 项正弦表。它默认恒等、不在执行路径上；色相≠0
  时哪个 HueSaturation 上链、饱和度是否被乘两次，**未做执行普查**（同 §6）。
- **清晰**：`clr` = 面板值，AMP 表按 clr/10 插值；面板 91..100 越过表尾，llr 取表尾。

## 5. 驱动 Edit 面板的正确姿势

- **能用**：给 trackbar 自己 `PostMessage(WM_KEYDOWN/UP)`：LEFT/RIGHT ±1、PRIOR/NEXT
  ∓/±10、HOME/END 两端。控件自己生成通知，安全。
- **会崩**：给父窗口合成 `WM_HSCROLL`；对自绘的 +/− 按钮发 `BM_CLICK`；对数值框
  `WM_SETTEXT + EN_KILLFOCUS` 只改文字不改值。
- attach 而不是 spawn（面板状态只在进程内存里，不落盘、不进注册表；重开就回机内值）。
- 常驻 Edit 用 `tools/keep_edit.py`（frida.spawn + 常驻，父进程退出 Edit 就没了）。
  **多个 keep_edit 残留时 Edit 启动后 20 秒内会自己退出**，先杀干净。
