# ZcTask3DLut(「高级色彩复制」那一级)—— 逐位复刻

> **2026-09-10 实测:两张不同的图 + 11 个 Creative Look,共 19 块 tile × 3 个 plane,
> 整块 tile(不只 valid rect)100.0000% 逐位,maxdiff = 0。**
> 表是**静态**的:一次抓到的表能跑通所有这些 tile。

* exec RVA **`0x36f340`**(VA `0x14036f340`,ret 在 `0x14036f976`),反汇编 `tools/disasm_3dlut.txt`。
* 模型 + 自检:`tools/lut3d_model.py`(`uv run python sony_repro/tools/lut3d_model.py`)。
* 便携表:`tools/lut3d_table.npz`(226 KB,`curve` + `points`),由 32 MB 的抓取包导出。
* 抓取包:`tools/lut3d_export_grid1.npz`(新,含 3D 表)、`tools/lut3d_export_cs_DSC02919-lut3d.npz`(旧,**没有** 3D 表)。
* 位置:YGamma 之后、SIMDSpica 之前;只有用户打开「高级色彩复制」时才跑。
* 输入输出都是三个 plane:`plane0 = Y`(0..16383)、`plane1 = Cr`、`plane2 = Cb`(uint16,中点 32768)。

---

## 0. 一句话

把 (Cr, Cb) 用 BT.601 的 1.402 / 1.772 还原成色差 **u ≈ R−Y**、**v ≈ B−Y**,
各自过一条 **|x|^(2/3) 的压缩曲线**换成 5+11 位的定点坐标,
再和 **Y>>9 + 9 位小数**一起,在一张 **33×33×33 → 3 通道 int16** 的表里做三线性插值,
出来的 (Y', u', v') 再用同一个 2×2 矩阵的逆变回 (Y, Cr, Cb)。

---

## 1. 描述符(`desc = [[[task+0x68]+0xc8] + 0x49920]`)

| 偏移 | 抓到的值 | 用途 |
|---|---|---|
| `+0x08` | ptr | 本 exec 不读 |
| `+0x10` | ptr | **同一张表的另一种排布**,本 exec 不读(见 §3.4) |
| `+0x18` | ptr | **3D 表**(cell store),`33^3 × 3 × 8 × int16` = 1 724 976 B |
| `+0x20` | 33 | v 轴步长 |
| `+0x28` | 33 | `[0x20]*[0x28] = 1089` = u 轴步长 |
| `+0x2c` | 5 | Y 移位量 = `14 − 5 = 9` |
| `+0x30` | 5 | 色度移位量 = `16 − 5 = 11` |
| `+0x34` | 511 | Y 小数掩码(9 位) |
| `+0x38` | 2047 | 色度小数掩码(11 位) |
| `+0x40` | ptr | 本 exec 不读 |
| `+0x48` | ptr | **1D 色度压缩曲线**,代码里用的是 `ptr + 0x10000` |
| `+0x58` | ptr | 本 exec 不读 |

`33 / 33 / 5 / 5 / 511 / 2047` 两次抓取完全一致。

## 2. 那个 `+0x10000` 是什么

**不是头,是负半轴。** 曲线是 `int16 curve[65537]`,代码持有的 `r11 = data + 0x10000`
是**下标 0 的位置**,访问写成 `word ptr [r11 + rcx*2]`,而 `rcx` 是 `movsxd` 来的**有符号**数,
范围 `[-32768, +32767]`。所以:

```
curve_signed[i] = int16 at (data + 0x10000 + 2*i),  i ∈ [-32768, 32767]
                = curve_flat[i + 32768]             (curve_flat 从 data 起算)
```

`0x10000` 之前的 64 KB **是被用的**,而且用得很凶:实测四块 tile 里下标最低到 **−32768**
(下界被 clamp 顶住),最高才 +2337 —— 负半轴是主力。

曲线本身是**奇对称、单调**的幂律压缩,逐位吻合:

```
curve_signed[i] = sign(i) * min( trunc( 32768 * (|i|/32768)^(2/3) ), 32767 )
```

32768 个正下标里 **32768/32768 全中**(唯一一处 `i = 32768` 溢出被 int16 饱和到 32767)。
`curve[0]=0, curve[1]=32, curve[2]=50, curve[3]=66 …` —— 中性附近分辨率极高,
这就是为什么 32 格的色度轴够用。

## 3. 3D 表(`[desc+0x18]`)

### 3.1 形状

`33 × 33 × 33` 个 **cell**,每个 cell **48 字节 = 3 个输出 × 8 个角 × int16**:

```
int16 grid[33][33][33][3][8];       // [iu][iv][iy][out][corner]
byte_offset(cell, out, k) = cell*48 + out*16 + k*2
cell = iu*1089 + iv*33 + iy
```

* 轴 0(步长 1089)= **u ≈ R−Y**(经曲线压缩后的 5 位整数部分)
* 轴 1(步长 33) = **v ≈ B−Y**
* 轴 2(步长 1) = **Y**,直接 `Y >> 9`
* 输出 0 = Y'、输出 1 = u'、输出 2 = v'

下标实际只到 **0..31**(5 位),所以 33³ 里的第 32 层(`grid[32]`、`grid[:,32]`、`grid[:,:,32]`)
**全 0、从不访问**;33 只是为了让"cell 里的 8 个角"能取到第 32 个格点。

### 3.2 cell store 是 33³ 格点表的冗余展开(已逐位验证)

cell `(iu,iv,iy)` 的第 `k` 个角 = 格点 `(iu+f0, iv+f1, iy+yf)`,`k` 是 **(f1,f0,yf) 的格雷码**:

| k | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| (f1,f0,yf) | 000 | 001 | 011 | 010 | 100 | 101 | 111 | 110 |

所以真正的数据只有 `int16 points[33][33][33][3]` = 107 811 个数 = 210 KB
(`tools/lut3d_table.npz` 里的 `points`),引擎把它按 cell 摊成 1.7 MB 是为了一次 cache line
拿满 8 个角。`Table.from_points()` 会把它还原成引擎那份。

### 3.3 数值范围

`points[...,0]`(Y')∈ [−1, 16317];`points[...,1]`(u')∈ [−11374, 11461];
`points[...,2]`(v')∈ [−14375, 14145]。格点值就是**输出本身的量级**(1:1),
因为八个权重和恒为 512、MAC 完再 `>>9` 正好把 512 除掉。

### 3.4 `[desc+0x10]` 是同一张表换了排布

`blk10[cell][k'][out]`(角在外、通道在内,而且 `k'` 是**普通二进制** `(yf,f0,f1)`),
和 `[desc+0x18]` 的 `grid[cell][out][k]` 逐位互为置换(已验证 `blk10[:, perm, :] == grid.transpose(0,2,1)`,
`perm = [0,4,6,2,1,5,7,3]`)。**本 exec 一次都不读它**,大概是给某条 SIMD 路径准备的。

## 4. 逐像素公式

```python
# 常量全部从 Edit.exe 的 rip 相对地址读出,见 §5
cb = double(Cb) - 32768.0
cr = double(Cr) - 32768.0

u  = float32(cb*3.7e-05  + cr*1.401988)     # cvtpd2ps
v  = float32(cr*0.000135 + cb*1.771978)

# comiss 两次:严格小于下界 → -32768.0,严格大于上界 → 32767.0,否则原值
iu = int(trunc( clamp(u, -32768.0f, 32767.0f) ))     # cvtsd2ss + cvttss2si
iv = int(trunc( clamp(v, -32768.0f, 32767.0f) ))

a = int32(curve_signed[iu]) + 0x8000        # ∈ [1, 65535]
b = int32(curve_signed[iv]) + 0x8000
f0, iu_c = a & 2047, a >> 11                # 11 位小数 + 5 位整数
f1, iv_c = b & 2047, b >> 11
yf, iy_c = Y & 511,  Y >> 9                 # Y 用 movzx 读,当无符号

F0, F1, yF = 2048-f0, 2048-f1, 512-yf
cell = iu_c*1089 + iv_c*33 + iy_c

# ---- 8 个三线性权重,全 int32,乘完再 >>3,加 0x40000 再 >>19 ----
W = lambda p, z: ((p * z) + 0x40000) >> 19
w2 = W((f0*yf)>>3, F1);  w6 = W((f0*yf)>>3, f1)
w3 = W((f0*yF)>>3, F1);  w7 = W((f0*yF)>>3, f1)
w1 = W((F0*yf)>>3, F1);  w5 = W((F0*yf)>>3, f1)
                         w4 = W((F0*yF)>>3, f1)
w0 = 512 - w7 - w6 - w5 - w4 - w3 - w2 - w1        # ← 余数,不是算出来的
```

* `w0` 是 **512 减掉其余七个**,不是独立算的 —— 所以权重和恒为 512,舍入误差全落在 `w0` 上。
  照抄这一点,否则会差 ±1。
* `>>3` 那一步是**先乘后截**,`(f0*yf)>>3` 会丢低 3 位,不能改成先约分。
* `0x40000 = 2^18`,`>>19` 是 `(x + half) >> 19` 的四舍五入(总位数 9+11+11 = 31,减 3 减 19 = 9 → 512)。

```python
# ---- 三个输出各自 8 项 MAC,int32,再 >>9 ----
acc[o] = sum_k( int16 grid[cell][o][k] * w[k] )     # o = 0,1,2
acc[o] >>= 9                                       # 算术右移

# ---- 写回 ----
Y_out  = 0 if acc[0] < 0 else (acc[0] & 0xFFFF)    # test/cmovs,只有下钳位,没有上钳位
                                                   # 且是 16 位存,超 65535 会**截断**不是饱和
ud = double(float32(acc[1]))                       # movd + cvtdq2ps + cvtps2pd
vd = double(float32(acc[2]))
Cb_out = clamp( trunc(vd*0.564341 - ud*5.4e-05) + 0x8000, 0, 65535 )   # → plane2
Cr_out = clamp( trunc(ud*0.713273 - vd*1.5e-05) + 0x8000, 0, 65535 )   # → plane1
```

`0.564341 = 1/1.771978`,`0.713273 = 1/1.401988` —— 出口就是入口那个 2×2 矩阵的逆。
注意 `acc[1]/acc[2]` 要**先过一遍 float32 再回 double**(`cvtdq2ps` / `cvtps2pd`),
直接用 int→double 在大值上会差一位。

## 7. 这一级到底干了什么(用模型跑出来的)

`Y ∈ {512, 2048, 4096, 8192, 12288, 16383}`:

| 输入 | Y 出 | 色度出 |
|---|---|---|
| 中性 `Cr=Cb=32768` | 448 / 1990 / 4046 / 8158 / 12270 / 16316 | 恒 32799(**+31 的中性偏置**) |
| `Cr=36000`(偏红) | 951 / 2143 / 4043 / 8153 / 12038 / 16295 | Cr 34218 → 35964 → **32801**(高光处色度彻底收回中性) |
| `Cr=40000, Cb=26000` | 2110 / 4390 / 6338 / 8574 / 10198 / 16250 | Cr 34146→38286→32801,Cb 31549→27621→32795 |

也就是:**暗部略提亮 / 中高调压 Y、饱和色压 Y 更多,并且在接近 Y 上限时把色度整个拉回中性**
—— 和「六块 tile 上 Y 掉 6..870、色度比 0.70..0.99、亮而饱和处最强」的观测一致。

## 8. 怎么重抓表

旧的 `tools/export_3dlut_capture.py`(和 `tools/lut3d_look_sweep.py`)只 dump 了 `[desc+0x48]`
(1D 曲线),**漏了 `[desc+0x18]` 的 3D 表** —— 只有这些包的话是复刻不出来的。

补了一个 `tools/lut3d_capture_grid.py`(Windows 端跑,frida + pywin32),
它额外读 `[desc+0x18]`(`33*33*33*48` = 1 724 976 B)、`[desc+0x10]` 和 `[desc+0x08]`:

```
python sony_repro\tools\lut3d_capture_grid.py <名字> [--nr auto] [--tiles 0,1,2,3]
# 前提:Edit.exe 已打开目标 ARW,且「高级色彩复制」已勾上
uv run python sony_repro/tools/lut3d_model.py --export-table sony_repro/tools/lut3d_export_<名字>.npz
```

第二步生成便携的 `lut3d_table.npz`(226 KB),之后 `Table.load()` 就不再需要 32 MB 的抓取包。
