# 一、ZcTaskSpica(RVA `0x358be0`,1961 字节)——**边缘自适应细锐化**

结论有把握,因为它的强度参数与 Sharpness **共用同两个设置字段**。

## 1.1 骨架

只动 **plane 0**,`uint16`,处理区是内缩 3 像素的矩形。分两遍:

```c
ctx  = *DAT_1405a8b18;                       /* 全局 Spica 参数单例 */
mode = 依 arw->vt[0xf8]() / vt[0xe8]() / vt[0x100]() / arw[0x144] 选 1/2/4/0x11
tbl  = FUN_140153c50(mode);
iso  = arw->vt[0xe0]();                      /* ISO */

/* ISO 三段线性插值:断点 tbl[0xc0] / tbl[0xc4] / tbl[0xc8],值 tbl[0xcc..0xd4] */
isoGain = piecewise_linear(iso);

/* ---- 第一遍:算细节修正,写进临时平面 tmp ---- */
for (y = y0+3; y < y1-3; ++y) for (x = x0+3; x < x1-3; ++x) {
    cls = this->vt[0x58](this, plane, &lo, &hi);      /* 纹理/边缘分类 -> 索引 */
    /* 由 cls 取两张表:ctx[0x28c8] 里每项 8 字节,ctx[0x28d0] 里每项 0x68 字节 */
    v   = this->vt[0x60](this, plane, x, y);          /* 方向滤波结果,9 位定点 */
    s   = plane[y][x];

    if (ctx[0x38] == 0) {
        tmp[y][x] = clamp((int)v >> 9, 0, 0x3fff);    /* 直通 */
    } else {
        d  = (v - (s << 9)) * isoGain;                /* 高频分量 */
        d2 = d * DAT_140466798;
        if (ctx[0x3c] != 0) {
            /* 三次 FUN_14035a1d0(软限幅曲线),取最小值 */
            lim = min(lim1, lim2, lim3) * ctx[0xc4] * DAT_140466790;
        } else lim = DAT_1404df248;
        tmp[y][x] = clamp(s - (int)(lim * DAT_1404667a4 * d * DAT_140466794), 0, 0x3fff);
    }
}

/* ---- 第二遍:按权重混回原图 ---- */
w = ((100 - st[0x2c4]) / 50.0f)              /* ← 与 Sharpness 互补 */
  * ((st[0x208] + 100) / 100.0f)             /* ← 与 Sharpness 同一个强度 S */
  * ctx[0x0c];

for (...) plane[y][x] = clamp(tmp[y][x] * w + plane[y][x] * (1 - w), 0, 32767);
```

## 1.2 最重要的一条:Spica 与 Sharpness 是同一把锐化的两端

```
ZcTaskSharpness :  权重 ∝  st[0x2c4] / 50
ZcTaskSpica     :  权重 ∝ (100 - st[0x2c4]) / 50
两者都再乘        (st[0x208] + 100) / 100
```

`st[0x208]` = 编辑参数 `0x801a`(锐化强度),`st[0x2c4]` = `0x901d`。
**`0x2c4` 是「细节 ↔ 轮廓」的分配器**:大 → 走 Sharpness(7×7 二项式,粗尺度),
小 → 走 Spica(方向滤波 + 纹理分类,细尺度)。

对 PIPELINE §7.9.5 那条「RMSE 12.5,模糊后掉到 6.8,说明一半是高频」的残差:
**只补 Sharpness 一端可能只解决一部分**,得看 `0x2c4` 实际取值。

## 1.3 没解出

* `this->vt[0x58]`(`FUN_140359390`,689 字节)—— 纹理/边缘分类器,输出一个索引。
* `this->vt[0x60]`(`FUN_1403599a0`,860 字节)—— 方向滤波,输出 9 位定点值。
* `FUN_14035a1d0` —— 软限幅曲线(被调三次,参数分别取 ctx 的
  `+0x48/0x4c/0x54/0x58`(正向)或 `+0x68/0x6c/0x74/0x78`(负向)、以及 `+0x94/0x98`)。
* `DAT_1405a8b18` 指向的参数单例的来源(`FUN_14035a600` 初始化,没读)。
* 常量 `DAT_140466790 / 794 / 798 / 1404667a4 / 1404df248` 没 dump。

# 二、ZcTaskITP(RVA `0x35af00`,2313 字节)——**多平面自适应滤波 + 由基底重建**

结论把握中等,骨架确定但核心滤波器没读。

## 2.1 骨架

```c
plane = task->planes[0];  w = plane[8]; h = plane[0xc];
calib = arw->vt[0xd8](arw, st[0x1e0]);
if (a[3] == 5) FUN_140172420(&P, calib);
else           FUN_1401724a0(&P, *(task+0x68), st, calib);   /* 组装噪声/增益参数 */

this->vt[0x60](this, task, &s78, &sA0);        /* 从 task 取两组标量 */
this->vt[0x58](this, &W, plane, rect);         /* W = 由 plane0 生成的浮点工作图 */

/* 六张 float 图,全是 (w,h),FUN_1401869f0 分配 */
buf1, bufD, buf50, bufF0, bufE8, bufE0

this->vt[0x110](this, bufF0, bufE8, W, w, h, rect, bufE0, ...);
this->vt[0x118](this, buf1, W,     w, h, bufF0, bufE0, rect, s78, sA0);
this->vt[0x190](this, bufD, buf50, W, w, h, bufE8, rect, 8.0f);

/* 新建 3 平面 uint16 图并写回 */
out.plane0[x] = clamp(bufD [x] + buf1[x], 0, 16383);
out.plane1[x] = clamp(buf1 [x],           0, 16383);
out.plane2[x] = clamp(buf50[x] + buf1[x], 0, 16383);
task->planes = out;                             /* FUN_14016b640 */
```

## 2.2 定性结论

* **`buf1` 是「基底 / 强度」平面**,直接成为输出 plane 1;
  plane 0 和 plane 2 是 **基底 + 各自的差分**(`bufD`、`buf50`)。
  这正是「把三通道拆成 `I` 与两条相对 `I` 的差」再重建的写法 ——
  和类名 **ITP(≈ ICtCp / IPT 的 I + 两个色差)** 一致。
* 由于下游 `ZcTaskSSCS` 把三个平面当 R/G/B 用(权重 32/64/32,plane1 权重加倍),
  **实际语义更像 `(R, G, B) → (G' + (R−G)', G', G' + (B−G)')`** ——
  即 **用处理过的绿/亮度基底重建 R 和 B,同时保住色差**。
  典型用途:亮度降噪后重建彩色、抑制伪色。
* 它排在 `RawNRSIMD` 之后、`SSCS` 之前,与上面这个用途吻合。
* `vt[0x58]` 的入口(`FUN_14035ad60`)把 uint16 平面按 **四个通道系数**
  (`param_5` 的 4 个 int16 × `param_7` × `DAT_140466990..99c`)转成 float —— 
  像是**噪声方差归一化**(把各通道按增益折算到同一噪声尺度)。
* `vt[0x110]` 的标量版 `FUN_140360910`(397 字节,最短、最可读)是
  **按权重图做二选一混合**:
  ```c
  m = max(w1[x], w2[x]);
  out[x] = m * A[x] + (1 - m) * B[x];
  ```
  这坐实了整段是「滤波版 vs 原版,按每像素置信度混合」的结构。

## 2.3 一条能对上的旁证

PIPELINE §7.4 说 SSCS「一个像素都没触发,因为整幅最大值只有 3043 而 lo=2380」。
ITP 就在 SSCS 上游,而且是唯一会**重建**平面数值的一步
(`out = base + delta`,三次 clamp 到 16383)。
**SSCS 看到的那个 3043 的量程是 ITP 定的**,§7.4 里「量程怎么来的还没解出」
这条应该从 ITP 这里继续查。

## 2.5 `vt[0x190]`(色差那一路)的四个基元核 —— 已解

`vt[0x190]` = `0x140363500` **不是滤波器,是编排器**。它一上来分配四个 float 缓冲
(`0x14035474b` 建对象、`0x1401869f0` 定尺寸 = arg5 × arg6 = w × h),
用**同一个源** `W`(arg4)填满,然后继续分配更多缓冲往下算。

四次派发都长一个样,只有槽号和目的缓冲不同:

```c
functor = { vptr = 0x140466678, x0, y0, x1, y1 };   /* 从 arg8 的 rect 抄来 */
this->vt[0x150](this, buf_a, W, &functor);
this->vt[0x158](this, buf_b, W, &functor);
this->vt[0x160](this, buf_c, W, &functor);
this->vt[0x168](this, buf_d, W, &functor);
```

> 认出这四个槽的关键是**栈帧**:8 次 push 之后 `lea rbp,[rsp-7]`,所以 `rbp+0x4f`
> 正好落在 rcx 的 home slot —— 那些 `[rbp+0x4f]` 不是别的对象,**就是 `this`**,
> 于是 `+0x150..+0x168` 直接在 `ZcTaskITP::vftable`(`0x1404667b8`)上查得到。
> 一开始误以为是另一个对象的表,白绕了一圈。functor 那张表(`0x140466678`)
> 指向 `0x14012d1b0` 一族十几字节的小 thunk,是框架的区域迭代器,**不含算术**。

四个核都是平铺循环,几百字节,一次读完:

| 槽 | 函数 | 大小 | 算式 |
|---|---|---|---|
| `+0x150` | `0x14035e750` | 272 | `out[y][x] = (in[y][x−2] + 6·in[y][x] + in[y][x+2]) / 8` |
| `+0x158` | `0x14035e860` | 496 | `out[y][x] = (in[y−2][x] + 6·in[y][x] + in[y+2][x]) / 8` |
| `+0x160` | `0x14035ea50` | 288 | `out[y][x−1] = (in[y][x−2] + in[y][x]) / 2` |
| `+0x168` | `0x14035eb70` | 288 | `out[y−1][x] = (in[y−2][x] + in[y][x]) / 2` |

常量都在 `.rdata`,一处不含糊:`6.0` @ `0x1404df118`、`0.125` @ `0x1404deadc`
(前两个核共用)、`0.5` @ `0x1404deb28`(后两个核共用)。
前两个核把首尾各两列/两行**原样拷贝**,不做滤波。

**四个核的抽头间距全是 2,即只取同色邻居。** 这是本节最重要的一条:

* 它独立坐实了 **ITP 的输入是马赛克**,与 `static-rawnr.md` §5.2 量到的
  「RawNRSIMD 跑在马赛克上、逐相位」对得上,也解释了执行链里 1 平面 → 3 平面
  为什么发生在这里(见 `measured-chroma-gap.md` §3)。
* 语义清楚了:前两个是**同色低通**(水平/垂直各一),后两个是把缺失位点
  **按同色两邻居取中点填上**(水平/垂直各一)。四个缓冲 = 水平假设与垂直假设
  各自的低通与插值 —— 这是**方向性 demosaic** 的前端。
* 下游 `vt[0x110]` 的标量版 `FUN_140360910` 已知是
  `m = max(w1, w2); out = m*A + (1−m)*B`(§2.2),正是**按每像素置信度在水平与
  垂直两个假设之间混合**。整条路子由此闭合。

这也解释了 `measured-chroma-gap.md` 量到的现象:色差之所以能干净到 8 位量化以下,
是因为重建**从同色低通开始**(`[1,0,6,0,1]/8`)再插值,而不是先插值再补救。

## 2.6 `vt[0x110]`(置信度权重那一路)—— 骨架与判据已解

`vt[0x110]` = `0x14035ecc0`(1272 字节)**也是编排器**,整个函数里没有一条 SSE 算术。
它分配 6 个缓冲,然后:

| 顺序 | 槽 | 函数 | 干什么 |
|---|---|---|---|
| 1 | `vt[0x68]` | `0x14035bff0` | 水平代价 |
| 2 | `vt[0xa0]` | `0x140363ae0` | 聚合 |
| 3 | `vt[0x70]` | `0x14035c170` | 垂直代价(与 1 同构) |
| 4 | `vt[0xa0]` | `0x140363ae0` | 聚合 |
| 5,6 | `vt[0xb0]` ×2 | `0x14035f1c0` | **判据** |
| 7 | `vt[0xb8]` | `0x140361950` | 未读 |

### 代价图 `vt[0x68]`(逐条读完)

```c
for (y = y0; y < y1; ++y)
  for (x = x0; x < x1 - 2; ++x) {
      v = (2*src[y][x] - src[y][x-2] - src[y][x+2]) * 0.25f;
      dstA[y][x] = v;                              /* 有符号,间距 2 的二阶差分 */
      dstB[y][x] = ((x ^ y) & 1) ? fabsf(v) : 0;   /* 只在绿位点上留幅度 */
  }
```

`0.25f` @ `0x1404deae4`;取绝对值是 `andps` 配 `0x1404e02a0`(四个 `0x7fffffff`)。

**`(x ^ y) & 1` 就是绿位点。** RGGB 下 R 在 (偶,偶)、B 在 (奇,奇),两个绿在
(偶,奇) 与 (奇,偶) —— 正是 x、y 奇偶相异的那些点。所以代价只在绿通道上量,
这是方向性 demosaic 的标准做法(绿的采样密度是 R/B 的两倍,方向判据只在它上面
才有一半的分辨率)。这条同时又一次证明**输入是马赛克**。

> ⚠️ 那个 `cvttsd2si` → `movd` → `cvtdq2ps` 的往返不要读出额外含义。
> 源里是 `(float)(int)(parity ? 1.0 : 0.0)`,double 常量 `1.0` 摆在 `0x1404ded88`,
> 编译器忠实地把它转成 int 再转回 float。语义就是一个 1/0 掩码。

### 判据 `vt[0xb0]`

```c
A = max(<初值>, costH[x] - p[0]) + p[2];
B = max(<初值>, costV[x] - p[1]) + p[2];
if (A + B > 0)  out[x] = A / (A + B);       /* comiss 守零 */
```

`p` 是个小参数块(`r14`:`+0` / `+4` 两个阈值、`+8` 一个 epsilon),多半来自
`FUN_1401724a0` 的参数组装。**这就是 §2.2 那个混合公式里缺的 `m`** ——
两个方向代价的归一化比。

> ⚠️ `max` 的另一个操作数(xmm2/xmm3 的入循环初值)还没回溯,所以「有没有下限 0」
> 这一条**没定**。形状 `m = A/(A+B)` 是确定的。

### 聚合 `vt[0xa0]`

自己不算数,按**列的奇偶**交替调 `vt[0x98]`(`0x1403644d0`)与 `vt[0x90]`
(`0x140363d80`),各返回一个标量,乘 `1/32`(`0x140466958`)写出;首尾各两列原样拷贝。
`vt[0x98]` 一上来把 9 个以上的栈 float 清零再累加 —— 是个窗口 gather。
`1/32` 说明窗口是 32 抽头;同一处常量区还有 `1/88`(`0x140466954`),`vt[0xb8]` 可能用它。

## 2.7 SIMD 侧 `0x3b2be0`:四方向活动度 → 各向异性控制图(**逐条解完,含全部常量**)

> 工具:`tools/itp_calls.py`(Stalker 找出每 tile 只跑一次的那一簇)→
> `tools/itp_stages.py`(15 个一次性反汇编 + 按指令形状定性,落盘 `disasm_<rva>.txt`)
> → `tools/read_rdata.py`(解常量池)→ `tools/itp_crit_params.py`(运行时读调参块)。

§2.4 末尾那条说得对:**SIMD 差异在 `vftable_meta_ptr` 那一列**。
`0x3b0370..0x3b4230` 这 15 个函数就是那一列,`0x3b2be0` 是其中最重的一个
(811 条指令,180 条向量)。它是 SIMD 独有的,标量侧没有同名孪生。

### 两个循环

**循环一 —— 四张方向活动度图。** 先分配 **4 张 w×h 的 float 图**,然后在 ROI 内
逐像素、按四个方向各算一次同一个量。设三个共线取样点为 `a, b, c`(b 在中间):

```
act(a,b,c) = |a + c − 2b| + |b − c| + |a − b|
```

即**二阶差的绝对值 + 两个一阶差的绝对值**(`vandnps` 配 `-0.0` = 取绝对值,
一共 12 次 = 四个方向 × 3 项)。四个方向的取样几何:

| 图 | 方向 | 三个取样点 | 说明 |
|---|---|---|---|
| buf0 | 水平 | `(y,x) (y,x+2) (y,x+4)` | **间距 2 = 同相位** |
| buf1 | 垂直 | `(y,x) (y+2,x) (y+4,x)` | 间距 2 = 同相位 |
| buf2 | 反对角 | `(y,x) (y+1,x−1) (y+2,x−2)` | 间距 1,在 Bayer 上落在绿格 |
| buf3 | 主对角 | `(y,x) (y+1,x+1) (y+2,x+2)` | 同上 |

轴向用间距 2、对角用间距 1,**正好都只取同色邻居**——与 §2.5 那四个基元核
「抽头间距全是 2」是同一条约束的两种表现,再次坐实 ITP 吃的是马赛克。

**循环二 —— 聚合、取比、映射。** 对四张图各做一次加权和,轴向与对角的核不同:

```
轴向(buf0 / buf1),5×3:        对角(buf2 / buf3),3×3:
    1   1   1                        1  1  1
    2   8   2                        1  4  1
    6   6   6                        1  1  1
    2   8   2                       和 = 12
    1   1   1
   和 = 48
```

归一化系数**按 CFA 相位选**,是本节最值得记的一处:

* 轴向乘 `ymm11` —— 一个 4 float 的循环模式,**按行奇偶**在
  `(1/32, 1/16, 1/32, 1/16)` 与 `(1/16, 1/32, 1/16, 1/32)` 之间二选一
  (`bt edx,0` + `cmovae`),所以实际系数同时取决于**行与列的奇偶**。
* 对角乘 `ymm12` —— 标量,按行奇偶取 `0.25` 或 `0.125`。
* 两边配成对:`48/16 = 12/4 = 3`、`48/32 = 12/8 = 1.5`。
  **分子分母被归一化到同一标度**,所以后面那个比值是无量纲的。
  相差 2 倍的那一档就是绿与红/蓝的采样密度差。

然后:

```
A_h  = max(Σbuf0 · n_ax,  P5)          n_ax ∈ {1/16, 1/32}(按相位)
A_v  = max(Σbuf1 · n_ax,  P5)          n_di ∈ {1/4,  1/8 }
A_d1 = max(Σbuf2 · n_di,  P5)
A_d2 = max(Σbuf3 · n_di,  P5)
r    = (A_h + A_v + 0.01) / (A_d1 + A_d2 + 0.01)      ← 0.01 是防零的 eps
out  = clamp( (P7 + P8 − r) · P9,  P6,  P7 )
```

(`P4` 在四处都被减掉一次,但实测为 0,见下;为省字这里已经略去。)

| `0.125` | `0x140469ce0` | 对角归一化,奇数行 |

调参块是**第 5 个参数**(入口 `[rsp+0x28]`;函数里写成 `[rsp+0x350]`,
7 个 push = 0x38 加 `sub rsp,0x2f0`,差正好 0x28 —— 核对过再用)。
`itp_crit_params.py` 三次命中逐字节相同:

```
+0x00  01 00 00 00 41 00 00 00 00 00 00 00 00 00 00 00
+0x10  3f 00 00 00 00 00 00 80 3f 00 00 00 3f 00 00 80
+0x20  3f cd cc 4c 3e cd cc 4c 3f 00 00 00 00 00 00 00
+0x30  01 00 00 80 3d 00 00 00 41 00 00 80 3b 00 00 00
```

> ⚠️ **我一开始把这些 float 记成「非对齐偏移 0x11/0x15/…」,那是读法不对。**
> 结构其实是 `#pragma pack(1)` 的 `{uint8 flag; float p[11];}`,步长 0x30 ——
> `+0x00` 的 `01` 是标志位,float 从 `+0x01` 开始,所以偏移自然全是 4k+1。
> `+0x30` 处 `01` 又起一条同构记录(`0.0625, 8.0, 1/256, …`),这一点确认了步长。
> **下次在 Sony 的参数块里看到「偏移差 1」,先怀疑前面有个 flag 字节,别当非对齐。**

于是这一级用到的是 `p[4..9]`:

| 槽 | 值 | 角色 |
|---|---|---|
| `p[4]` | **0** | 各方向减掉的底 —— 实测为 0,这一步是空操作 |
| `p[5]` | **1.0** | 减完之后的下限(四个方向各一次) |
| `p[6]` | **0.5** | 输出下钳 |
| `p[7]` | **1.0** | 输出上钳,同时是仿射里的常数项 |
| `p[8]` | **0.2** | 比值的偏置 |
| `p[9]` | **0.8** | 斜率 |

代进去:

```
out = clamp( (1.2 − r) · 0.8,  0.5,  1.0 )
```

**两个边界值得单独算一遍,因为它们把这张图的性质定死了:**

1. 上钳 `1.0` 要求 `r ≤ −0.05` —— `r` 恒非负,**上钳够不到**。
   实际值域是 `[0.5, 0.96)`。
2. `r ≥ 0.575` 就压到下钳 `0.5`。而四个方向各有 `max(·, 1.0)` 的地板,
   **平坦区四项全等于 1,`r = 2.01/2.01 = 1`,输出 `clamp(0.16,…) = 0.5`**。

所以这张图的读法是:**默认 0.5,只有对角活动度显著超过轴向(约 1.74 倍以上)
才抬起来,最高 0.96。** 它对 H↔V 对称、也对两条对角对称,
**所以它不是「水平还是垂直」的方向选择**,而是一张**各向异性/对角优势**的控制图。

### ⚠️ 更正:这一级不是色度降噪

`itp_stages.py` 的形状分类把它标成「邻域滤波 + 有判据 + 有除法」,
我据此判断它是 `ZcTaskRawNRSIMD` 那种 sigma 滤波、是索尼色度降噪的头号候选。
**读完之后这个判断不成立**:那 12 个 `vandnps` 是取绝对值不是阈值掩码,
那个除法是取比值不是「除以被接受的抽头数」,而且它**根本不输出图像**,
输出的是一张 `[0.5, 0.96)` 的控制图。**形状分类只能用来排序,不能用来定性。**

(色度那一头的结论没变,仍在 `measured-chroma-gap.md` §2.6:压色差的是
最后一级 `ZcTaskSIMDMarble`,已按实测形状落地为 `sony/chromanr.py`。)

### 顺带解掉 §2.6 的一个 ⚠️

标量侧 `vt[0xb0]`(`0x35f1c0`)的 `A = max(<初值>, costH − p[0]) + p[2]`
里那个「入循环初值」当时没回溯出来。SIMD 侧这一级是同族写法,而这里
**那个操作数确凿是调参块里的一个常数**(`p[5] = 1.0`),不是 0、也不是循环变量。
形状对上了,但**这是旁证不是证明** —— 两边是不同的函数,标量侧那一处仍需自己回溯。

### 还没定的
