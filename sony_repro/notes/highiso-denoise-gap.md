## 0. 结论速览

1. **「amount ≥ 50 渲染完全一致」不成立 —— 那是 llr 的钳位,不是引擎的。** Edit 的自动档 = 手动 50(逐位 100%),
   但 75 和 100 各自不同:细带亮度噪声 3.68 → 2.42 → 1.38(/255,1–2 px 带),8 位成品只有 8.5% / 5.2% 像素相同。
   引擎在 50 以上做了两件事:**RawNR 阈值表整体 ×(1 + t/100)、混合表 tbl3 = (t+100)/200·1024**(用这两项重算,
   三块 tile 100.000% 逐位),以及 **`ZcTaskYNR` 上链**(50 以下不跑,75/100 每 tile 一次;3×3 中值按 P = t 混入,
   llr 的 `lumanr._ynr_strip` 对引擎出口 99.9%)。tile 外扩 +10 px 也是 YNR 带来的。llr 现在把 >50 钳回 50,所以用户看到的
   「一致」是我们自己造成的。
2. **颜色偏差是低频的、只在暗部、来自降噪路径本身,根因是 llr 的 RawNR 入口把黑电平以下的值钳到黑。**
   `denoise._pack_normalise` 做 `clip((x−black)/scale, 0, 1)`;ISO 25600 时 7.4% 的像素在黑电平以下,钳掉负噪声后
   sigma 滤波的均值系统性上偏(整幅路径对引擎 RawNR 出口只有 34% 逐位、均值 +3.3 级,R 相位最重 20%),
   引擎吃的是原始值(含负噪声)—— 同一 tile 直接跑核 100% 逐位。落到成品:Y<0.15 的暗部 16px 低频
   ΔY +2.6、ΔCr +2.8、ΔCb −0.7(/255),|C| 只有 Edit 的 0.63–0.81,肉眼是暗部发灰偏紫红。关降噪时两边一致(±0.3),
   RawNR/ITP/Marble 各级在**引擎自己的输入**上都逐位,所以此前所有 tile 级验证都看不见它。
3. **「大颗粒没去掉」= 8–32 px 的色度斑,不是亮度。** llr 自动档 Cb/Cr 在 ≤2 px 与 Edit 相当,4–8 px 起 3 倍、
   8–16 px 3.6 倍、16–32 px 2.8 倍;亮度各带与 Edit 持平或更低(离线链没 Sharpness/Spica,细带更低)。
   落在 **Marble 的色差清理**:它的阈值标定随 ISO 变(本片导出时 ctx p34/p38/p40/p48/p4c = −7/2222/184/487/640,
   生产里写死的是 ISO 2000 那张的 −4/982/158/187/652),换成本片的值 tile 残差减半,但仍不逐位 —— Marble 在高 ISO 上
   还有一处没对上(未解)。
4. 推荐改法(按收益):① RawNR 入口不钳负值(一行改动,暗部色偏归零,见 §6);② Marble 标定逐张取(先按 ISO 插值/抓表,
   再逆向来源);③ 手动档 >50:阈值×(1+t/100) + blend 表 + 接上 YNR(三件事的公式和验证都在 §3);④ 离线对比链补 Sharpness/Spica。

## 3. amount ≥ 50:引擎到底改了什么

`highiso_amount_probe.py` 在同一次导出里抓:按 **this 指针的 vtable** 归类的执行普查(RawNRSIMD 的 exec 与 SIMDSpica 共用

| | 量 50(=自动) | 75 | 100 |
|---|---|---|---|
| `+0xc0000..c00cc`(52 项) | 512 | 768 | 1024 |
| `+0xc0100/104/108` 逐平面强度 | 48(=标签) | 72 | 96 |
| `+0xc011c` t | 0 | 50 | 100 |
| tbl0(阈值)@0/2048/4096 | 72/270/369(=标签曲线,逐项 100%) | 108/405/553(×1.5) | 144/540/738(×2) |

| 档 | 逐位 | 只换表(blend 留 512) | 只换 blend(表留 50 的) |
|---|---|---|---|
| 50 | 100.000% ×3 | — | — |
| 75 | 100.000% / 100.000% / 100.000%(1 块 max 65) | 94.7% | 55.2% |
| 100 | 99.981% / 100.000% / 100.000% | 95.4% | 41.6% |

对引擎出口 **99.91% / 99.87%**(5×5 只有 11%,纯 3×3 中值 99.87%,所以掩码几乎没起作用——T=8191 在这张片上没命中)。

## 4. 逐级定位:差在 llr 的 RawNR 入口,不在任何算子

### 4.1 引擎自己的输入上,三级全逐位(ISO 25600 也成立)

* RawNR(标签:lo 0 / hi 3072 / base 72 / slope 396,gain **128**,limit 1023,ISO 强度 1.0):3 块 100.000%。
* ITP:关档 3 块、50 档 2 块,三平面 100.000%(max 1)。
* Marble:见 §5,**不逐位**。

### 4.2 但 llr 真实整幅路径不等于引擎(`highiso_frame_check.py`)

引擎 RawNR 入口 tile 在 rawpy 马赛克里原样找到(位置 (2000,3026),整块 100%);`denoise_raw_inplace` 跑完同位置
对引擎出口只有 **34.06% 逐位,max 297,均值 +3.28 级**,R 相位 20%、其余 37–40%。tile 大小无关(单 tile / +200 边 / 整幅
三种都是 34.06%),直接调核 100% —— 问题在 `SonyRawNRDenoiser` 外面那层:

```
_pack_normalise: clip((x − black) / scale, 0, 1)      ← 黑电平以下的 7.4% 像素被钳到黑
_to_levels:      clip(p·span + black, 0, 16383)       ← 回到电平时已经回不去了(往返 max|err| = 512)
```

sigma 滤波对被单边截断的噪声取均值,均值自然上偏;R 相位电平最低、截断最多,所以偏红。引擎(和 llr 的关档路径)
喂 ITP 的是含负噪声的原始值,`static-rawnr` 早记过「引擎吃的是黑电平未减的原始值」,但 normalise 那一步的 clip 没人量过 ——
ISO ≤ 2000 的验证片子里黑电平以下的像素太少,看不出来。

## 7. 结论 / 未解 / 下一步

**结论**

1. 差距的性质:亮度侧 llr 不输 Edit(细带更低只是离线链缺锐化);差距在**色度**,而且是**低频**(8–32 px 色斑)加一个
   **暗部低频色偏**(ΔCr +2.8、ΔY +2.6,|C| ×0.63)。
2. 落点:色偏在 **RawNR 入口的钳位**(`denoise._pack_normalise`),色斑在 **Marble 的 ISO 标定**;RawNR / ITP 算子本身在
   ISO 25600 仍逐位。
3. 「≥50 一致」是 llr 的钳位;引擎 >50 = 阈值 ×(1+t/100) + blend 表(逐位验证)+ YNR 上链(99.9%)。

**未解**

* Marble 高 ISO 的剩余差异(换 ctx 后 |Δ| 仍 120–150/65535)及 p34..p50 的来源。
* YNR 那 0.1% 的不一致(边界或 Sobel 掩码的取整)。
* `m25`(t<0)那档的 RawNR 参数没抓(只导了成品:4–8 px 带比 50 档还高,与 blend 256 / 阈值 ×0.5 的预期一致,未验证)。

**下一步(按收益/成本)**

### 9.1 Marble 的 ctx 不是 ISO 的函数:是 ARW 里的 SR2 标签 `0x794a..0x795e`

上一轮以为 p34..p50 "calib+0x1000 块里没有原值",其实就在 **calib+0x109c..+0x10c4** —— 上一轮看的是 ISO 2000 那张的块

### 9.2 "换 ctx 后仍不逐位"的那一处:因子 8(cnr1_c070 / cnr4_fe70)

ISO 25600 捕获里的 1/N 平面是 77×133(=616/8 × 1064/8),不是 154×266;exec 在 `0x14038a76a`:`factor = calib[0x109e]==1 ? 8 : 4`,
并按同一标志在 cnr1/cnr4 两处换函数。两个新 helper 是**标量通用版**:

* `cnr1_c070`(f×f 盒):Y 求和 `>> 2·log2 f`(f=8:>>6,+32),半分辨率色度 `f × f/2` 盒 `>> (2·log2 f − 1)`(>>5,+16),零→1,
  远端残块保持全除数 —— 生产的 `box()` 直接参数化。
* `cnr4_fe70`(×f 双线性上采样):权重表 `0x1405596c0/0x140559740/0x1405597c0/0x140559840`(A0/A1/B1/B0,各 32 项),
  行相位 (2r+1)/2f、列相位 (2c+1)/f,权重 = (2f−(2r+1))·(f−(2c+1)) 等四个乘积,f=8 时和恰为 128(f=4 的表是同一式 ×4),
  `+64 >> 7`;写出网格偏移 (+f/2, +f/4)(f=4 时是 (+2,+1)),前 f/2 行、f/4 列引擎不写。
* cnr2/cnr3/scratch(pad 6)/fin/blend 与因子无关;顺带确认 cnr3 只写 6..hs+5 的核心区,外环是陈旧内存(不进链路)。

### 9.4 YNR 那 0.1%:Sobel 掩码算在中值平面上

`highiso_probe_q100b.npz` 两块 YNR tile:掩码在原平面上算 → 546 / 897 个像素不一致(99.92% / 99.87%),不一致处 97% 是
